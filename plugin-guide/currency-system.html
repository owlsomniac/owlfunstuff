Overview

The Currency System is a complete, settings-driven economy for your forum. Members earn currency by posting, spend it in a customizable shop, sell items back individually or in bulk, and bank their savings — all without you touching a line of code.

Staff hand out or take back currency and items from an admin panel (to one member, several, or everyone at once), each with an optional reason, and every transaction can be logged per member. Items can carry rarity tiers with colored borders, and a wallet “pill” keeps each member’s balance in view.

It is the core plugin the others build on: Currency System Extras adds theming and extra UI, and the Minigame Suite adds games that pay out through it. Load order, top to bottom on your Plugins page: Currency System → Currency System Extras → Minigame Suite. The Currency System must load first.

Instruction Manual

The Setup Instructions inside the plugin’s own settings are a quick-start checklist. This is the full, plain-English walkthrough of every feature.

Welcome. This manual explains what every feature of the Currency System (CS) plugin does and, step by step, how to set it up. It is written for a forum admin who has never used the plugin and is not technical — it assumes you know nothing about how CS works, and by the end you will be able to use every feature.

Every setting described here lives on the tabs of THIS plugin. To reach them: go to your forum's Admin area, open Plugins, click the Currency System plugin, then open its Settings. The Settings are split into tabs (pages), and this manual walks through them one at a time. The exact tab names are:

  • Setup Instructions
  • Currency
  • Boards
  • Shops
  • Logs
  • Styling + CSS
  • Key Permissions

This manual COMPLEMENTS the built-in Setup Instructions tab. That tab is your quick-start checklist — the short list of steps to get running. This manual is the long-form reference that explains the WHY behind each step and every option in detail. If you just want to get going fast, follow the Setup Instructions tab; when you want to understand or fine-tune a feature, come here.

CORE CONCEPTS TO LEARN FIRST

Before touching any settings, learn these four ideas. Everything else in the plugin builds on them.

Wallet vs Bank

Every member has two balances:

  • WALLET — this is spendable money. It is the number shown in the little "currency pill" (a small floating badge on the page). Everything a member earns or is given lands in the WALLET: posting rewards, admin grants, and money from selling items all pay into the wallet. Buying things in the shop spends from the wallet.
  • BANK — this is savings. Money in the bank is safe and set aside, but it cannot be spent directly. To spend bank money a member must first move it back to the wallet.

Members move money between the two themselves using the DEPOSIT and WITHDRAW buttons on the Inventory page (the page you will build at #hcs-inventory):

  • DEPOSIT moves money from wallet into bank.
  • WITHDRAW moves money from bank back into wallet.

You, as admin, do not need to manage this — it is a convenience for members who want to "save up" without accidentally spending.

Amounts and decimals (stored in hundredths)

Internally the plugin stores all money in hundredths (100 internal units = 1 of your currency). This is a behind-the-scenes detail that exists so decimal amounts like 0.15 or 2.50 work exactly, with no rounding errors. You never have to think about hundredths — everywhere you type an amount, and everywhere a member sees an amount, it is shown as a normal number (for example 0.15, 1, 12.50). Just enter and read ordinary amounts.

The "Blank vs 0" convention

Many settings behave differently when you leave them EMPTY versus when you type the number 0. This distinction matters throughout the plugin, so learn it now:

  • BLANK (empty field) usually means "use the default" or "no limit / fall back to the general rule."
  • 0 (the digit zero) usually means "explicitly none" or "exactly zero."

The clearest example is an item's Sell Amount on the Shops tab: leaving it BLANK means the item sells at your global sale price, while typing 0 means the item cannot be sold at all. Blank and 0 are NOT the same thing. Each setting's help text tells you what blank does for that specific field; when in doubt, read it.

THE THREE CUSTOM PAGES YOU MUST CREATE

WHAT IT IS: The plugin's three main screens — the Shop, the Inventory, and the staff Admin Grant panel — do not appear on their own. Each one renders into a Custom Page that YOU create on your forum. If you skip this, those screens simply never show up. (This is also covered on the Setup Instructions tab; it is repeated here because nothing else in the manual works until it is done.)

WHERE: This is not a plugin Settings tab — you create Custom Pages in your forum's main Admin area, not inside the plugin. But it is the prerequisite for everything, so do it first.

How to set it up

You will create THREE separate Custom Pages. For each one, paste the single matching line of code (a "container div") into the page's content box. The page's name and web address (URL) are entirely up to you — only the id in the code matters. Paste exactly:

  1. Shop page — paste: <div id="hcs-shop"></div>
  2. Inventory page — paste: <div id="hcs-inventory"></div>
  3. Admin Grant page — paste: <div id="hcs-admin"></div>

That is the entire content of each page — one line each. When a member visits the page, the plugin finds that container and fills it in.

What each page becomes:

  • #hcs-shop — the shop, where members spend currency on items.
  • #hcs-inventory — the member's own inventory, wallet + bank strip (with Deposit / Withdraw), selling, and — if you install the Extras add-on — their history panel.
  • #hcs-admin — the staff-only grant panel. Regular members who open this page see nothing useful; only your Manager Groups and forum Admins see the controls.

Make the pages reachable — add a menu link

Creating a Custom Page does NOT add it to your forum's menu, so at this point members still have no way to reach it. You have to add the link yourself. For each page you want members to use:

  1. Copy the page's web address (URL) — the one you gave it when you created it, e.g. /shop.
  2. Open your forum's navigation menu editor and add a new link that points to that URL.

• In ProBoards this is the Navigation / menu editor in your Admin area (the same place the default Home / Members / Search tabs are managed).
• If you use the Better Nav Bar plugin, add the link on its "Nav Bar" tab (Main Nav Bar Links) instead.

  1. Give the link a clear label, such as "Shop" or "Inventory", and save.

Add links for the Shop and Inventory pages so members can find them. The Admin Grant page is staff-only — you can leave it OFF the public menu and just bookmark its URL, or add it to a staff-only menu.

Example

Create a Custom Page titled "Shop" with the address /shop and put only <div id="hcs-shop"></div> in it. Create another titled "My Inventory" at /inventory containing only <div id="hcs-inventory"></div> . Create a third titled "Grant Panel" at /grant containing only <div id="hcs-admin"></div> . Then add links to the Shop and Inventory pages in your forum menu so members can find them.

Tips

  • If a page shows up completely blank, 99% of the time the container div is missing, misspelled, or on the wrong page. Re-check the exact spelling, including the quotes and the hcs- prefix.
  • Do not put more than the one div line in — no need for any other HTML.
  • You can name the pages and URLs anything; the plugin only looks for the id.

NAMING YOUR CURRENCY

WHAT IT IS: This is where you give your currency its name and symbol, and choose which staff groups are allowed to hand out or take away currency and items.

WHERE: The "Currency" tab.

How to set it up

On the Currency tab, fill in three settings:

  1. "Currency Name" — what your currency is called (for example Coins, Gold, Credits, Pebbles). If you leave it blank, the plugin uses "Coins".
  2. "Currency Symbol" — a short symbol or emoji shown next to amounts (for example $). If you leave it blank, the plugin uses the star symbol ✦.
  3. "Manager Groups" — choose which member groups are allowed to add and remove currency and items. These are your economy staff — the people who will use the Admin Grant Panel. This is a group picker; you can select more than one group.

Forum Admins ALWAYS qualify as managers automatically, whether or not you list them here. Use Manager Groups to extend that power to non-admin staff (for example a "Game Moderators" group) without making them full forum admins.

Example

Set Currency Name to "Gold", Currency Symbol to a coin emoji, and Manager Groups to your "Event Staff" group. Now amounts appear as things like "12.50 Gold" with the coin next to them, and both your forum Admins and everyone in Event Staff can open the grant panel and hand out Gold.

Tips

  • Keep the symbol short — it appears inline next to numbers all over the plugin.
  • Only give Manager Groups to people you trust with the economy; managers can also REMOVE currency and items, and grant to ALL members at once.

EARNING CURRENCY BY POSTING

WHAT IT IS: This is how members earn currency simply by posting on your forum. You decide which boards pay out and how much. There are TWO kinds of earning board, and a board that you do not list here earns nothing at all.

WHERE: The "Boards" tab. It has two sections — WORD-COUNT BOARDS and FLAT-RATE BOARDS — each with its own list and its own Global Daily Cap.

A quick note on how you name a board: each rule asks for the board's numeric ID. You find that number in the board's web address (URL). The tab provides a board picker to help you select it.

Board type 1 — Word-Count boards (reward scales with post length)

On a word-count board, longer posts earn more. Each word-count board rule has these fields:

  • "Word-Count Board" — which board this rule applies to.
  • "Word Count Floor" — the word count that earns the base amount. Posts at or above this length scale up; shorter posts scale down. Blank = 100.
  • "Amount at Floor" — how much a post earns when it is exactly at the floor length. Blank = 1.
  • "Amount per 10 words" — extra currency added for every full 10 words ABOVE the floor. Blank = 0.15.
  • "Amount Cap" — the most a single post here can ever earn, no matter how long. Blank = 10.
  • "Daily Cap" — an optional per-board daily limit (explained under DAILY CAPS below). Blank = this board shares the Global Daily Cap.

THE MATH IN PLAIN ENGLISH:

  • A post exactly at the floor earns the "Amount at Floor".
  • For every complete block of 10 words ABOVE the floor, add the "Amount per 10 words".
  • The total never goes above the "Amount Cap".
  • Very short posts (below the floor) scale DOWN proportionally, but never drop below a tiny minimum of 0.10.

Word-Count worked example

Say a board is set to: Word Count Floor 100, Amount at Floor 1, Amount per 10 words 0.15, Amount Cap 10.

  • A 100-word post earns 1 (exactly at the floor).
  • A 150-word post is 50 words over the floor = 5 full blocks of 10, so 5 × 0.15 = 0.75 extra, for a total of 1.75.
  • A 1,000-word post would calculate very high, but the Amount Cap of 10 stops it — it earns 10.
  • A short 30-word post is below the floor, so it scales down to a small amount (but never less than 0.10).

Board type 2 — Flat-Rate boards (fixed amount per post)

On a flat-rate board, every post earns the same amount regardless of length. Each flat-rate board rule has:

  • "Flat-Rate Board" — which board this rule applies to.
  • "Amount per Post" — the currency earned for any post here, long or short. Blank = 1.
  • "Daily Cap" — an optional per-board daily limit. Blank = this board shares the flat-rate Global Daily Cap.

Flat-Rate worked example

Set a board's Amount per Post to 2. Now every single post on that board earns exactly 2, whether it is one word or one thousand.

Daily caps — how they limit earning per day

Daily caps stop members from farming currency endlessly. Important rules:

  • WORD-COUNT and FLAT-RATE earnings are tracked SEPARATELY. The two Global Daily Caps and the two board lists never mix.
  • The "Global Daily Cap" (there is one for word-count and one for flat-rate) is a SHARED pool. Every board of that type that leaves its own Daily Cap blank draws from this one shared pool together.
  • A board that sets ITS OWN Daily Cap gets its own SEPARATE pool at that value (which can be higher OR lower than the global). It no longer touches the shared pool.
  • Blank or 0 for a Global Daily Cap = no shared limit at all.
  • All daily caps reset at UTC midnight (a fixed time each day, worldwide — not each member's local midnight).
  • Each post only ever pays out ONCE. Editing or re-saving a post does not pay again.

Daily caps worked example

Suppose the word-count Global Daily Cap is 100. You have four word-count boards:

  • Board A sets its own Daily Cap to 500.
  • Board B sets its own Daily Cap to 20.
  • Boards C and D leave their Daily Cap blank.

Result per member, per day:

  • Board A has its own pool: a member can earn up to 500/day on Board A alone.
  • Board B has its own pool: up to 20/day on Board B alone.
  • Boards C and D share the global pool of 100: a member can earn up to 100/day across C and D combined.

Tips

  • A board not listed on either list earns nothing. Leaving both lists empty means nobody earns by posting at all.
  • If you want a busy chat/spam board to not pay (to avoid low-effort farming), simply do not list it.
  • Because caps reset at UTC midnight, the "daily" boundary may not line up with your local midnight — that is normal.

BUILDING THE SHOP

WHAT IT IS: The shop is where members spend their currency on items you create. You define every item and its price here.

WHERE: The "Shops" tab. It holds the Global Sale Price, the Rarity Tiers & Colors list (covered in the next section), and the Shop Items list.

The Global Sale Price

"Global Sale Price (%)" is the default price members get back when they SELL an item, written as a percentage of what the item cost. For example 50 means items sell back for half their cost. Default: 50. Any single item can override this with its own Sell Amount.

Adding an item — the fields

Under "Shop Items", add one row per item. For each item:

  • "Name" — the item's display name. Blank = "Item".
  • "ID" — REQUIRED. A unique identifier used to track the item everywhere (in inventories, grants, and sales). No spaces, and it must be unique across all items. Never leave this blank. If two items share an ID, or an ID changes later, member inventories can break.
  • "Category" — an optional grouping label. Items are grouped by category in the shop. Blank = uncategorised.
  • "Item Rarity" — an optional tier name. It MUST exactly match a tier from your Rarity Tiers & Colors list (see the next section). Blank = none.
  • "Cost" — the buy price. Blank = 0 (free).
  • "Sell Amount" — how much the item sells for from inventory. BLANK = use the Global Sale Price. 0 = the item CANNOT be sold. Any other number overrides the global percentage for this item. Remember: blank does NOT make an item unsellable — only 0 does.
  • "Description" — optional details shown for the item.
  • "Image URL" — an optional image for the item. Blank = none.
  • "Image Width" and "Image Height" — optional per-item size overrides (for example 64px or 100%). If blank, the item uses the global Shop Icon Size set on the Styling + CSS tab. Use these when you want a particular item bigger or smaller than the rest.

What members see in the shop

The shop renders as a grid of item cards, grouped by Category. A member clicks a card to buy that item. There is also a multi-buy panel that lets them choose a quantity and buy several at once. Buying spends from the WALLET; if the wallet is short, the purchase is refused.

Example

Add an item: Name "Health Potion", ID "health_potion", Category "Consumables", Item Rarity "Common", Cost 25, Sell Amount blank, Description "Restores your spirits.", Image URL a link to a potion picture. With the Global Sale Price at 50, this potion buys for 25 and sells back for about 12.50 (half). To make a one-of-a-kind trophy that can never be sold, give it Sell Amount 0.

Tips

  • Choose a clear, permanent ID for each item (like health_potion) and never reuse or rename it once members own it.
  • If you want an item that can be bought but not sold, set Sell Amount to 0 — not blank.
  • If an item's Item Rarity does not exactly match a tier name (including capitalisation), its rarity color and sorting will not apply.

ITEM RARITY (TIERS, COLORS, AND BORDERS)

WHAT IT IS: Rarity lets you rank items into tiers (like Common, Rare, Legendary), give each tier a color, and optionally show a colored border around items and sort them by rarity.

WHERE: Two tabs work together. The tier names and their colors live on the "Shops" tab under "Rarity Tiers & Colors". The master ON/OFF switch and the border thickness live on the "Styling + CSS" tab.

The master switch: Rarity Borders

On the Styling + CSS tab, "Rarity Borders" is the master switch for the whole rarity feature. Default: No (off). When you set it to Yes it does TWO things at once: it turns on the colored borders around items AND it turns on sort-by-rarity. When it is off, colors and rarity sorting do not appear even if you have defined tiers.

The Rarity Tiers & Colors list (order matters)

On the Shops tab, the "Rarity Tiers & Colors" list is your master list of tiers. Each row has:

  • "Rarity Tier" — a tier name, for example Common, Uncommon, Rare.
  • "Rarity Color" — the color for that tier (for example yellow for Common, green for Uncommon).

ORDER MATTERS. Add rows from LOWEST rarity to HIGHEST rarity, top to bottom, because that order is exactly what drives the sort-by-rarity feature. If you list them out of order, items will sort in that wrong order.

Each shop item's "Item Rarity" must EXACTLY match one of these tier names (same spelling, same capitalisation) for its color and sorting to work.

Border widths

When Rarity Borders is on, two settings on the Styling + CSS tab control how thick the colored ring is:

  • "Rarity Border Width (Shop)" — thickness on shop items. Blank = 1px (for example enter 2 or 2px).
  • "Rarity Border Width (Inventory)" — thickness on inventory items. Blank = 1px.

Example

On the Shops tab, add tiers in this order: Common (grey), Uncommon (green), Rare (blue), Epic (purple), Legendary (orange). On the Styling + CSS tab set Rarity Borders to Yes and Rarity Border Width (Shop) to 2px. Now give your Health Potion the Item Rarity "Common" and a rare sword the Item Rarity "Rare". In the shop, the potion gets a grey ring and the sword a blue ring, and items sort Common → Legendary.

Tips

  • If colors or sorting are not showing, first check the master switch (Rarity Borders = Yes on Styling + CSS).
  • The most common mistake is a typo between an item's Item Rarity and the tier name — they must match exactly.
  • Reordering the tier list reorders how items sort — arrange lowest to highest.

THE INVENTORY PAGE (WHAT MEMBERS SEE)

WHAT IT IS: The Inventory page is each member's personal screen showing their money and the items they own, and it is where they move money between wallet and bank and sell items back.

WHERE: This is the Custom Page you built with <div id="hcs-inventory"></div> . Its look is tuned on the Styling + CSS tab (Inventory header, icon size, scroll height), but its behaviour is described here so you know what members can do.

The wallet + bank strip

At the top of the Inventory page is a strip showing the member's WALLET and BANK balances, with DEPOSIT and WITHDRAW buttons. Deposit moves wallet money into the bank; Withdraw moves bank money back to the wallet. Members manage this themselves.

The item grid and selling a single item

Below the strip is the member's item grid — every item they own. To sell one item, the member opens that item and sells it; they receive its Sell Amount (or the Global Sale Price if the item's Sell Amount is blank), paid into the wallet. Items with Sell Amount 0 cannot be sold.

Bulk Sell

For selling many items at once there is a "Sell Items" button in the inventory header. It opens a bulk-sell panel where the member picks which items to sell. The panel starts with NOTHING selected. It offers a "Select all" checkbox, and each row has an "All" option to sell every copy of that item. As they select, a running preview shows how many items and how much money the sale will bring, and they confirm to sell everything selected in one go.

Example

A member has earned 40 Gold and bought three potions and a sword. On the Inventory page they see Wallet 40 / Bank 0. They Deposit 30 to save it (Wallet 10 / Bank 30). Later they click "Sell Items", tick "Select all", and sell the three potions and the sword at once, and the total lands back in their wallet.

Tips

  • If the item area gets long, it scrolls; you can set its height with "Inventory Scroll Height (px)" on the Styling + CSS tab (blank/0 = default 260).
  • Bank money is safe from shop spending — encourage members to bank what they want to keep.

THE ADMIN GRANT PANEL (STAFF ONLY)

WHAT IT IS: The Admin Grant Panel is the staff tool for handing out — or taking away — currency and items. It also includes an "Unstuck a Member" repair tool.

WHERE: This is the Custom Page you built with <div id="hcs-admin"></div> . Only your Manager Groups and forum Admins see the controls; anyone else who opens the page sees "Staff only." The panel's title can be set on the Styling + CSS tab ("Admin Grant Panel").

How to grant or remove

  1. In the "Username or ID" box, choose who receives the action. You can enter ONE member, or SEVERAL separated by commas. Type part of a name to pick from a search list, or type member IDs directly.
  2. Or, to reach everyone, tick "Grant to ALL members on record" — this applies to every member the plugin has seen, and ignores the username box.
  3. Under the currency action, choose "Add" or "Remove" and type an Amount (the amount is optional — leave it if you only want to grant items).
  4. Under the item action, choose "Add" or "Remove" and pick one or more items with quantities (also optional).
  5. Optionally type a "Reason" (maximum 200 characters). The reason is shown to the recipient with the grant, for example "Prize for winning the art contest."
  6. Click "Review". A confirmation popup summarises exactly who, what, and the reason BEFORE anything is applied. Removals and all-member actions are shown with a danger style so you pause. Confirm to apply, or close to cancel.

You must enter at least one recipient (or tick ALL members) and at least a currency amount or one item, or Review will ask you to fix it.

How delivery works (important)

Grants are delivered through a shared "inbox" and applied when each member next loads the forum:

  • A grant to YOURSELF applies IMMEDIATELY — you see it without reloading.
  • A grant to OTHER members is QUEUED. It applies the next time each of those members loads ANY forum page. So a member who is offline receives it automatically the next time they visit.

When the grant applies, the recipient sees a NOTICE POPUP listing what an admin granted (or removed), with your Reason underneath if you wrote one. The heading lines and the popup title of that notice can be customised on the Styling + CSS tab (Grant Notice, Remove Notice, Notice Popup Title).

Grant example

To reward a contest winner named Ava with 50 Gold and a trophy: type "Ava" in the username box and pick her from the list, set the currency action to Add with Amount 50, set the item action to Add and pick your "Trophy" item (quantity 1), write the Reason "1st place — Summer Art Contest", and click Review. Confirm. Because Ava is not you, the grant queues; the next time Ava loads a page she gets 50 Gold, the trophy, and a popup that says an admin granted her those with your reason shown.

The "Unstuck a Member" tool

ProBoards limits how much data a single member's saved row can hold. If a very active member's row fills up, new grants and purchases can silently stop saving. The "Unstuck a Member" panel (below the grant controls) fixes this by clearing stored queues and history that take up room — WITHOUT touching money or items the member actually has.

  1. Enter the member (username or ID) and click "Check what's stored". It reports counts for the member's pending inbox, notices, tombstones (apply-history), transaction history, and items.
  2. Tick which parts to clear:

• "Pending inbox" — undelivered queued grants (cleared first, so clearing tombstones can never re-credit a pending grant).
• "Notices" — the stored not-yet-shown popups.
• "Tombstones (apply-history)" — the internal record of already-applied grants. Safe to clear and frees the most space.
• "Transaction history" — the member's logged history entries.

  1. Click "Clear selected" and confirm.

Clearing does NOT remove anything already earned or spent — it only frees the stored queues and history that were taking up row space. The member's wallet, bank, and items are untouched. Clearing Tombstones and old Transaction history is the safe, high-impact choice when someone is stuck.

Tips

  • If a grant fails with a message about the row being full, use Unstuck on that member (or on your own account for a failed self-grant), clearing Tombstones and Transaction history, then try again.
  • Because "Grant to ALL members" is powerful and irreversible in bulk, the Review step deliberately flags it as a danger action — read the summary before confirming.

STYLING AND APPEARANCE

WHAT IT IS: The Styling + CSS tab controls the structural look the base plugin ships with — headers, titles, the wording of grant popups, icon sizes, scrolling, and how the currency pill behaves. Out of the box the plugin uses a neutral, semi-transparent "frosted" look that reads on both light and dark forums, so you can leave everything blank and it still looks fine.

WHERE: The "Styling + CSS" tab.

Page Headers

A page header is a banner across the top of a whole page. Each of the three pages has its own content field: "Shop — Content", "Inventory — Content", and "Admin — Content". If what you type looks like an image link it is shown as an image; otherwise it is shown as styled text. Blank = no header. Shared controls apply to ALL three at once:

  • "Text Size" — font size for text, or max-height for an image (for example 24px). Blank = theme default.
  • "Text Style" — any of Bold, Italic, Underline (text only).
  • "Page Header Text Color" — banner text color. Blank = the Heading color.
  • "Alignment" — Left, Center, or Right. Default: Left.

Panel Headers

These are the titles shown INSIDE each panel (blank = no title):

  • "Shop Buy Panel"
  • "Inventory Panel"
  • "Admin Grant Panel"

The font styling of these titles is set in the Currency System Extras add-on, not here.

Custom Messages

These control the wording members see when you grant or remove:

  • "Grant Notice" — the heading above the list of granted things. Blank = "An Admin granted you:".
  • "Remove Notice" — the heading above the list of removed things. Blank = "An Admin removed:".
  • "Notice Popup Title" — the title of the popup itself. Blank = "Notice".

Icons, scroll, and the currency pill

  • "Shop Icon Size" — size of item images in the shop grid. Default 80px. Per-item Image Width/Height override it.
  • "Inventory Icon Size" — inventory thumbnail size. Blank = 48px.
  • "Inventory Scroll Height (px)" — how tall the inventory item area gets before it scrolls. Blank/0 = default 260.
  • "HUD Scroll Behaviour" — whether the currency pill (the currency + active-buffs bar) stays on screen as you scroll ("Stays visible while scrolling", pinned — the default) or scrolls off with the rest of the page ("Scrolls off with the page").

IMPORTANT — the color theme lives in the Extras add-on

The base Currency System plugin ships only the neutral frosted look and the structural options above. The full COLOR THEME — every palette color and opacity, the currency pill's colors and size, and the fonts for panel titles — is set in the SEPARATE "Currency System Extras" add-on. If you want to recolor the plugin to match your forum's theme, install Currency System Extras; without it, you get the default frosted appearance. Leaving the styling fields blank keeps the default look.

Example

Set Shop — Content to "Welcome to the Shop", Alignment to Center, Text Style to Bold, and Text Size to 28px. Members now see a bold, centered "Welcome to the Shop" banner above the shop grid, while the rest keeps the default frosted styling.

HISTORY AND LOGGING

WHAT IT IS: This controls whether the plugin RECORDS a history of economy actions (earnings, purchases, grants, and so on) into each member's data.

WHERE: The "Logs" tab.

IMPORTANT UP FRONT: the base plugin only RECORDS history. The member-facing history PANEL that members read, and the staff transaction-log VIEWER that staff browse, are both provided by the separate Currency System Extras add-on. Without Extras, history is still recorded — you just do not have the built-in screens to view it.

Enable Member History

"Enable Member History" is the master switch. Default: On. Off = nothing is ever logged. On = the actions you select below are written to each member's history.

Record These Actions

"Record These Actions" is a checklist of which action types get written. Leaving it EMPTY records ONLY admin grants and removals — this is the recommended default, because those are the audit trail that matters most. The available types are: Post earnings, Purchases, Sales, Deposits, Withdrawals, Admin currency grants, Admin currency removals, Admin item grants, Admin item removals.

WARNING: every recorded action uses one of a member's LIMITED saved history lines (and a multi-item purchase uses one line per item). ProBoards caps how much data a single member's row can hold, so turning on many types can exhaust that limit and cause saves to fail for your most active members. Turn on extra types SPARINGLY — only log what you truly need.

Readable Labels

"Readable Labels" shows log entries in plain English instead of raw internal codes. Default: On. Leave it on.

Retention (how long entries are kept)

History is automatically trimmed so it never grows without bound:

  • Most entries are kept about 15 days.
  • Admin grant/remove entries are kept longer, about 30 days (they are the audit trail).
  • A member keeps at most about 25 entries total.

Older or excess entries fall off automatically.

Example

Leave Enable Member History On, leave Record These Actions empty, and leave Readable Labels On. Now only admin grants and removals are logged, in plain English, for about 30 days — a clean audit trail with almost no risk of filling up member rows. If you later want to also log purchases, tick only "Purchases" and watch that active members do not start hitting save errors.

Tips

  • The recommended safe setup is: History On, Record These Actions empty, Readable Labels On.
  • If members report grants or purchases failing to save, one likely cause is too many recorded action types filling their rows — trim the list and use Unstuck.
  • To actually SEE the history in-forum, install Currency System Extras.

THE FIVE PROBOARDS KEYS AND THEIR PERMISSIONS

WHAT IT IS: "Keys" are where ProBoards plugins store their data. The Currency System uses five keys. The plugin's import creates them; you mostly just confirm they exist and set two permissions. Understanding what each stores helps you avoid accidentally destroying member data.

WHERE: The keys themselves are on the plugin's Keys tab; the permissions you must set are on the "Key Permissions" tab.

What each key stores (in plain terms)

  • "user_data" — each member's wallet, bank, items, and history. This is the heart of the plugin. NEVER delete or rename it, or every member loses everything they own.
  • "grant_inbox" — the shared list of pending admin grants waiting to be picked up by their recipients.
  • "forum_data" — the shared member directory (so the grant panel can find members by name).
  • "reward_claimed" — remembers which posts have already paid out, so a single post can never pay twice.
  • "chatter_today" — each member's daily earning counters (used to enforce the daily caps).

Key Permissions you must set

On the Key Permissions tab, set these two to Members & Staff (Read + Write):

  • "grant_inbox" — so members can RECEIVE and claim the currency and item grants staff send them. Without write access here, queued grants can never apply to members.
  • "chatter_today" — so members can RECORD their post earnings against the daily caps. (If you disable earning by posting entirely, this one can be set to Staff only instead.)

These matter because a member's own browser does the work of claiming grants and recording earnings; if members cannot write to these keys, grants never arrive and posting never pays.

Tips

  • If grants never reach members, the first thing to check is that grant_inbox is Members & Staff (Read + Write).
  • If posting does not pay out, check chatter_today's permission.
  • Treat user_data as sacred — do not delete, rename, or reset it on a live forum.

GOOD-TO-KNOW FACTS

A few final facts that save you trouble:

  • The plugin ships as TWO JavaScript components (the second holds just the Admin panel, split out because of size). Both are minified (compressed) code. Do NOT hand-edit the minified code — it is generated, and editing it by hand will likely break the plugin.
  • GUESTS (visitors who are not logged in) never see the currency pill and never hold a balance. Only real members have wallets.
  • Companion plugins build ON TOP of this one and must load AFTER it. The Currency System is the CORE plugin and must load FIRST. In particular:

• "Currency System Extras" — adds the full color theme, the member history panel, the staff transaction-log viewer, card-flip descriptions, and item cards in posts. Load it after the core plugin.
• "Minigame Suite" — mini-games that award currency. Load it after the core plugin (and after Extras).

  • Plugins load top-to-bottom on your forum's Plugins page, so drag Currency System ABOVE its companions. If a companion loads first it will not find the economy and will fail.

You are ready

That covers every feature. A good first-run order is: create the three Custom Pages, name your currency and set Manager Groups, confirm the keys and the two Key Permissions, set up a couple of earning boards, add a few shop items, then test by posting, buying, selling, and sending yourself a grant.
