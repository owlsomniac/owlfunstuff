Overview

Better Nav Bar replaces your forum’s navigation bar with its own. It builds three levels of menus, and can also add a search box, a notification bell with an unread badge, a floating welcome / login panel, scroll-to-top and scroll-to-bottom buttons, and header & logo overrides.

It is completely standalone — no other plugin required — but when the Currency System (with Extras) is installed, its default “Match Currency System” theme makes the nav inherit that palette automatically, so everything looks like one set. Otherwise, pick the built-in Dark or Light theme and fine-tune the colors yourself.

Instruction Manual

The Setup Instructions inside the plugin’s own settings are a quick-start checklist. This is the full, plain-English walkthrough of every feature.

This manual explains every feature of the Better Nav Bar plugin (BNB) and shows you, step by step, how to set each one up. It is written for a forum admin who has never used the plugin before, so nothing is assumed.

Everything you configure lives on the tabs (pages) of THIS plugin — you do not edit any other plugin or any theme file to use it. The four tabs are: "Setup Instructions", "Nav Bar", "Other Features", and "Styling & CSS". Whenever a step below says which tab to use, that is a tab inside this same plugin.

This manual complements the built-in "Setup Instructions" tab: that tab is a short 6-step quick-start, while this manual is the full reference that walks through every single setting.

Better Nav Bar works entirely on its own — NO other plugin is required. It is a standalone replacement for your forum's navigation bar. (One optional bonus: if you also run the Currency System plugin with its Extras add-on, BNB's default color theme automatically matches that plugin's colors — but this is optional and BNB is fully usable without it.)

WHAT BETTER NAV BAR DOES (THE BIG PICTURE)

Better Nav Bar removes your forum's default navigation bar and puts its own in its place. The replacement bar is a full multi-level menu system (top buttons, dropdowns, and a third nested level) and it also bundles several extra tools you can switch on or off:

  • A multi-level navigation menu — your main buttons, their dropdowns, and dropdowns-within-dropdowns.
  • A search box — BNB's own styled search field.
  • A notification bell — a bell with an unread badge that opens a pop-up list of notifications (and, optionally, personal messages).
  • A welcome / login panel — a small floating panel greeting members (with a Logout link) or guests (with Login and Register links).
  • Scroll-to-top / scroll-to-bottom buttons — two floating buttons that jump to the top or bottom of the page.
  • Header and logo overrides — restyle or replace your forum's banner image and logo.

STANDALONE, WITH AN OPTIONAL BONUS: BNB needs no companion plugin. However, if the Currency System plugin (with its "Extras") is installed, BNB's default theme ("Match Currency System") makes the whole nav bar inherit that plugin's color palette automatically, so everything matches as one unit. If you do not run the Currency System, that same default simply falls back to a neutral frosted look — nothing breaks.

A FEW FACTS THAT APPLY EVERYWHERE (worth memorising):

  • Color fields: type a hex code WITHOUT the leading "#". For example, type "1a1a1a", not "#1a1a1a".
  • Size / width / radius / offset fields: a bare number is treated as pixels (px). Typing "8" means 8px. You may also type units yourself, e.g. "8px", "12em".
  • Opacity fields: use a number from 0 to 100, where 0 is fully see-through and 100 is fully solid.
  • "Blank = inherit": almost every color and size field says what it falls back to when you leave it empty. Leaving a field blank is a normal, safe choice — it just keeps the inherited value.

FEATURE 1 — BUILDING YOUR MENU (THE NAV BAR TAB)

WHAT IT IS: This is the heart of the plugin — the actual menu your visitors click. It has THREE levels, each built in its own list on the "Nav Bar" tab:

  • Main Nav Bar Links — the top-level buttons that sit across the bar.
  • Sub Menu Links — the items that drop down when you hover a main button.
  • Sub-sub Links — a third level that flies out from a sub-item (a dropdown inside a dropdown).

WHICH TAB: "Nav Bar".

How the three levels connect (READ THIS FIRST)

Each level is a separate list of rows. You connect a child to its parent by TYPING the parent's exact "Link Text" into the child's "Parent Link Name" field.

  • A Sub Menu Link's "Parent Link Name" must exactly match a Main link's "Link Text".
  • A Sub-sub Link's "Parent Link Name" must exactly match a Sub link's "Link Text".

This match is CASE-SENSITIVE and must be EXACT — spaces, capitalisation and punctuation all count. If the parent name is even slightly off (e.g. "community" instead of "Community", or a trailing space), the child silently will NOT appear. There is no error message; the item just does not show. When a child is missing, the first thing to check is that its "Parent Link Name" is a character-for-character copy of the parent's "Link Text".

The fields on every menu row (same on all three levels)

Each row you add — on any of the three lists — has these fields:

  • "Link Text" — the words shown on the button/item. Leave blank for no link.
  • "URL" — where the link goes when clicked. IMPORTANT: leave the URL BLANK to turn the item into a non-clickable HEADING. A heading is not a link, but it STILL opens its dropdown if it has children. This is how you make a top button that only exists to reveal a menu.
  • "Opens In" — choose "Same tab" (default) or "New tab" for where the link opens.
  • "Visibility" — who can see this item. Options: "Everyone" (the default when left blank), "Members only", "Specific groups", or "Guests only".
  • "Member Groups" — only used when Visibility is "Specific groups". Pick the member group(s) that should see the item.

(On the Sub and Sub-sub lists there is also the "Parent Link Name" field described above, which comes first.)

TWO HELPFUL BEHAVIOURS:

  • Current-page highlight: the link that points at the page a visitor is currently on is highlighted automatically. You do not set this per-row; it just happens. (You can style that highlight color — see the Menu Styling section.)
  • Headings that open menus: because a blank-URL item still opens its dropdown, you can have a top button like "Community" that is not itself a link but reveals a menu of real links underneath.

Step by step — build a menu

  1. Go to the "Nav Bar" tab.
  2. Under "Main Nav Bar Links", add a row for each top button. Fill in "Link Text" and, if it should be clickable, a "URL". Set "Opens In" and "Visibility" as needed.
  3. Under "Sub Menu Links", add a row for each dropdown item. In its "Parent Link Name", type the EXACT "Link Text" of the main button it belongs under. Fill in its own "Link Text" and "URL".
  4. Under "Sub-sub Links", add a row for each third-level item. In its "Parent Link Name", type the EXACT "Link Text" of the SUB item it belongs under.
  5. Save. Hover your top buttons on the forum to test the dropdowns.

Worked example — a "Community" menu

Goal: a top button called "Community" that itself is not a link but opens a dropdown. Inside it: a "Members" link, and a "Staff" item that is itself just a heading opening a further dropdown of individual staff pages.

Main Nav Bar Links — add one row:

  • Link Text: Community
  • URL: (leave BLANK — this makes "Community" a heading that only opens its dropdown)
  • Opens In: Same tab • Visibility: Everyone

Sub Menu Links — add two rows:
Row A → Parent Link Name: Community | Link Text: Members | URL: /members | Visibility: Everyone
Row B → Parent Link Name: Community | Link Text: Staff | URL: (leave BLANK — "Staff" becomes a heading that opens its own dropdown)

Sub-sub Links — add rows that hang under "Staff":
Row 1 → Parent Link Name: Staff | Link Text: Admins | URL: /members?group=admin
Row 2 → Parent Link Name: Staff | Link Text: Moderators | URL: /members?group=mods

Result: hovering "Community" opens a dropdown with "Members" and "Staff"; hovering "Staff" flies out a further menu with "Admins" and "Moderators". Note that "Community" and "Staff" both have blank URLs, so they are not clickable links — they only reveal their menus.

Tips and gotchas — menus

  • Exact match wins: 99% of "my sub-menu is missing" problems are a "Parent Link Name" that does not exactly match the parent's "Link Text". Copy and paste to be safe.
  • Blank URL = heading: use this on purpose for grouping buttons; do not leave a URL blank by accident on an item you meant to be clickable.
  • Order matters visually: rows appear in the order you list them, so arrange them the way you want them shown.
  • Visibility "Specific groups" needs the "Member Groups" field filled, or nobody in particular is targeted.
  • Deleting rows on the Main and Sub lists prompts you to confirm (these lists ask before deleting), so you will not lose a row by a single misclick.

FEATURE 2 — PICKING A COLOR THEME (STYLING & CSS TAB)

WHAT IT IS: The overall "base look" of the whole nav bar and its dropdowns. You pick one base palette, then (optionally) fine-tune individual colors on top of it.

WHICH TAB: "Styling & CSS", the "Color Theme" setting at the very top.

The three choices for "Color Theme":

  • "Match Currency System" — THIS IS THE DEFAULT. The nav bar inherits the Currency System plugin's palette so the entire nav matches that plugin as one unit. If the Currency System is not installed, it falls back to a neutral frosted look. IMPORTANT: in this mode the individual color pickers further down the tab (all the Main / Sub / Sub-sub link colors) are IGNORED. Sizes and spacing still apply, but hand-picked colors do not.
  • "Dark" — a ready-made dark palette. Standalone; needs no other plugin. You CAN fine-tune it with the color pickers.
  • "Light" — a ready-made light palette. Also standalone and fine-tunable with the color pickers.

THE KEY RULE TO REMEMBER: the default is "Match Currency System", and while that mode is selected, your individual color pickers do nothing. If you want to hand-pick any nav colors, you MUST first switch "Color Theme" to "Dark" or "Light". Only then do the color pickers take effect. (You may see older intro text that calls the default "Dark" — that is wrong. The real default is "Match Currency System".)

Step by step — choose a theme

  1. Go to "Styling & CSS".
  2. At the top, find "Color Theme".
  3. To match the Currency System automatically, leave it on "Match Currency System" (the default) and stop — the pickers below are ignored on purpose.
  4. To hand-pick colors, change it to "Dark" or "Light" first, then adjust the pickers in the "Menu Styling" section below.
  5. Save.

WORKED EXAMPLE: You want a dark bar but with your brand's green buttons. Set "Color Theme" to "Dark", then in "Menu Styling → MAIN LINKS" set "Main — Link Background" to your green hex (no "#"). The bar is dark, the buttons are green. If you had left the theme on "Match Currency System", that green picker would have been ignored.

TIP: leave a picker blank to keep the chosen theme's base color for that element — you only need to fill the pickers you actually want to change.

FEATURE 3 — MENU STYLING (COLORS & SIZING) (STYLING & CSS TAB)

WHAT IT IS: The colors and sizes of the menu itself — the top buttons, the dropdowns, and the nested flyouts.

WHICH TAB: "Styling & CSS", the "Menu Styling" section.

REMINDER: these color pickers only take effect when "Color Theme" is set to "Dark" or "Light". In "Match Currency System" mode they are ignored (though the sizing fields still apply).

The three-tier color inheritance (how blanks fill themselves in)

BNB saves you work by letting lower menu levels inherit colors from higher ones:

  • MAIN links are the base — the colors you set here are the starting point for everything.
  • SUB links (dropdowns) inherit from Main by default. Any Sub picker you leave blank copies the matching Main color; any Sub picker you fill overrides just that one color.
  • SUB-SUB links (nested flyouts) inherit from Main by default too — UNLESS you set "Sub-sub — Inherit Sub?" to "Yes", in which case they inherit from Sub instead. Again, a blank picker inherits and a filled picker overrides just that one color.

So: fill only the pickers you want to change; leave the rest blank and they fall into line automatically.

Picker group — LAYOUT & SIZING (applies to every menu level)

  • "Corner Radius" — how rounded the link corners are. Blank = 4px. (A bare number is px, so "4" = 4px.)
  • "Link Padding" — the space inside each link around its text. Blank = 10px 20px (that is 10px top/bottom, 20px left/right).
  • "Font Size" — text size of the links. Blank = 16px.
  • "Side Padding (edges)" — how far the whole bar is inset from the screen edges; controls how flush the first link (left) and the search bar (right) sit to the edges. Use "0" for flush, "20px" for breathing room. Blank keeps your theme's default.

Picker group — MAIN LINKS (top bar)

These are the base colors the Sub and Sub-sub levels inherit from. The order is: the link's own colors, then hover, then border, then the current-page highlight.

  • "Main — Text" — the link text color. Blank = the theme base color.
  • "Main — Link Background" — the button fill behind each link. Blank = transparent (the bar shows through).
  • "Main — Hover Text" — text color while the pointer is over the link. Blank = theme base.
  • "Main — Hover Background" — fill behind the link on hover. Blank = theme base.
  • "Main — Border Color" — outline around each link. It only shows if you also set a border width. Blank = theme base.
  • "Main — Border Width" — thickness of that outline, e.g. "1" or "1px". Blank = none (no border shows).
  • "Main — Current Page Text" — text color of the link for the page you are currently on. Blank = same as a normal link.
  • "Main — Current Page Background" — background of the current-page link (e.g. highlight "Home" while on the home page). Blank = same as a normal link.

Picker group — SUB MENUS (dropdowns)

The dropdown that opens from a Main link. Same pickers, same order as Main, plus a PANEL pair at the bottom for the dropdown box itself. Sub links inherit their text, hover and border colors from Main unless you override a picker.

  • "Sub — Text" — dropdown link text. Blank = inherits Main text.
  • "Sub — Hover Text" — text on hover. Blank = inherits Main hover text.
  • "Sub — Hover Background" — the highlight bar as you move down the menu. Blank = inherits Main hover background.
  • "Sub — Border Color" — outline around each dropdown link (needs a width to show). Blank = inherits Main border.
  • "Sub — Border Width" — thickness, e.g. "1px". Blank = inherits Main.
  • "Sub — Panel Background" — the color of the dropdown BOX the links sit in. The rows are transparent, so this is the color you actually see behind them. Blank = theme base.
  • "Sub — Panel Border" — outline around the dropdown box. Blank = theme base.

Picker group — NESTED MENUS (Sub-sub)

The flyout that opens from a Sub link (the third level). Same layout and pickers as Sub, plus its OWN panel pair (independent of the Sub panel).

  • "Sub-sub — Inherit Sub?" — "No" (default) means the nested menu follows the MAIN colors; "Yes" means it follows the SUB colors instead. Individual pickers below still override either way.
  • "Sub-sub — Text", "Sub-sub — Hover Text", "Sub-sub — Hover Background", "Sub-sub — Border Color", "Sub-sub — Border Width" — same meanings as the Sub pickers; blank = inherits the base level (Main, or Sub when "Inherit Sub?" is Yes).
  • "Sub-sub — Panel Background" — the nested flyout's box color, independent of the Sub panel. Blank = the default panel look.
  • "Sub-sub — Panel Border" — outline around the nested flyout box. Blank = the default.

Worked example + tips — menu styling

EXAMPLE: You are on the "Dark" theme and want white link text, a subtle hover, and a highlighted current page.

  1. "Color Theme" = Dark (so pickers work).
  2. "Main — Text" = ffffff (white, no "#").
  3. "Main — Hover Background" = 333333.
  4. "Main — Current Page Background" = 0a84ff (a blue for the active button).
  5. Leave every Sub and Sub-sub picker blank — they inherit these automatically, so your dropdowns match with zero extra work.

TIPS:

  • Set a "Border Color" AND a "Border Width" together — a border color alone shows nothing without a width.
  • To restyle just the dropdown box without touching the links, use only "Sub — Panel Background".
  • If a nested flyout should look like its parent dropdown rather than the top bar, set "Sub-sub — Inherit Sub?" to "Yes".

FEATURE 4 — SEARCH BAR (STYLING & CSS TAB)

WHAT IT IS: BNB's own search box, pinned to the left of the second row of the nav. It is ON by default. When a member types and submits, it runs your forum's standard ProBoards search.

WHICH TAB: "Styling & CSS", the "Search Bar" section (behavior) plus its "APPEARANCE" sub-section (looks).

Behavior settings

  • "Show Search Bar" — On (default) or Off.
  • "Placeholder Text" — the greyed-out prompt inside the empty box, e.g. "Search the forum". Shows "Search" if blank.
  • "Submit Method" — how the typed text is sent. "GET" (default) puts it in the URL exactly like ProBoards' own search; only choose "POST" if your search endpoint specifically requires it.
  • "Advanced Button Tooltip" — the hover tooltip / screen-reader label for the gear (advanced) button. Shows "Advanced search" if blank.
  • "Search Button Icon" — the icon on the magnifier button; type any emoji/character (e.g. the magnifier glyph) or paste an image URL. Shows a magnifier if blank.
  • "Advanced Button Icon" — the icon on the gear (advanced) button; any emoji/character or an image URL. Shows a gear if blank.

Appearance settings

The bar has TWO surfaces: the outer PANEL (the whole bar) and the inner FIELD (the well where the member types). Enter hex colors without the "#".

  • "Panel Background" — fill of the whole bar. Blank = matches the nav-button background.
  • "Field Background" — fill of the inner typing well. Blank = becomes a 30%-opacity tint of the Field Text color, so the well looks translucent over the panel.
  • "Field Text" — color of the text the member types (and the faint placeholder). Blank = matches nav-button text.
  • "Icon Color" — tints the magnifier and gear glyphs. Blank = matches the nav link text. (Only affects glyph/emoji icons; image-URL icons keep their own colors.)
  • "Highlight" — the accent shown while the box is focused; only the border changes color, so the field never fills and the text stays readable. Blank = uses the nav hover accent.
  • "Border Color" — the resting outline. Blank = matches nav-button border.
  • "Border Width" — outline thickness, e.g. "1px". Blank = matches nav-button border width.
  • "Corner Radius" — how rounded the box is, e.g. "4px". Blank = matches nav corner radius.
  • "Bar Size (padding)" — padding around the whole bar; this sets its overall size (the input grows/shrinks with it). Blank = 6px 10px.
  • "Font Size" — text size inside the box. Blank = matches nav font size.
  • "Box Width" — width of the typing area, e.g. "150px" or "12em" (a bare number is px). Blank = 150px.

Step by step, example, tips — search

  1. In "Styling & CSS → Search Bar", leave "Show Search Bar" On.
  2. Set "Placeholder Text" to something friendly, e.g. "Search the forum".
  3. Leave "Submit Method" on GET unless you know your search needs POST.
  4. Leave every appearance color blank to inherit the nav look, or fill just the ones you want to change.

EXAMPLE: a wider box with your own placeholder — set "Placeholder Text" = "Search MyForum" and "Box Width" = "220px". Leave the colors blank so it matches the rest of the bar.

TIPS:

  • Blank colors inherit the nav buttons, so the search bar matches automatically — you rarely need to touch the colors.
  • The search targets ProBoards' standard search, so GET is almost always correct.
  • Icons accept emoji OR an image URL, so you can use a branded icon image if you prefer.

FEATURE 5 — NOTIFICATION BELL (STYLING & CSS TAB)

WHAT IT IS: A bell icon with a small unread "badge" (counter), shown to logged-in MEMBERS to the left of the greeting. Clicking it opens a pop-up (a "modal") listing the member's notifications and, optionally, their unread personal messages. It is ON by default.

WHICH TAB: "Styling & CSS", the "Notification Bell" section.

HOW THE BADGE WORKS: the number on the badge shows what is NEW since the member last opened the bell. Once they open it, that "new" count resets — so the badge is a "what changed since I last looked" indicator, not a running total of everything.

The settings

  • "Show Notification Bell" — On (default) or Off. When on, members get a bell + counter left of the greeting.
  • "Bell Icon" — an emoji/character (e.g. a bell) or an image URL. Default is a bell emoji.
  • "Bell Icon Color" — tints emoji/text icons only (ignored for image icons). Blank = inherits the text color.
  • "Bell Icon Size" — e.g. "20px". Default 20px.
  • "Counter Background Color" — the badge fill when there IS something new. Default red.
  • "Counter Text Color" — the badge number color when there is something new. Default white.
  • "Counter Background (at 0)" — the badge fill when there is nothing new (count is 0). Blank = a quiet grey.
  • "Counter Text (at 0)" — the badge number color at 0. Blank = the unread counter text color.
  • "Modal Heading" — the title at the top of the pop-up. Default "Notifications".
  • "Empty State Text" — shown when there are no notifications. Default "You have no new notifications."
  • '"See all" Link Label' — label for the link at the top of the modal. Default "See all Notifications".
  • "Notif: 'See all Messages' Label" — label for the SECOND link in the bell. Default "See all Messages".
  • "Include Personal Messages" — On (default) also lists unread personal messages in the bell; Off shows notifications only.
  • "Max Items Shown (advanced)" — caps how many entries appear in the modal. Default 30.

Step by step, example, tips — bell

  1. In "Styling & CSS → Notification Bell", leave "Show Notification Bell" On.
  2. Optionally change "Bell Icon" (emoji or image URL) and "Bell Icon Size".
  3. Set the badge colors: "Counter Background Color" / "Counter Text Color" for the "new" state, and the two "(at 0)" fields for the quiet, nothing-new state.
  4. Reword "Modal Heading", "Empty State Text", and the two "See all" labels to your taste.
  5. Decide "Include Personal Messages" (On to fold PMs into the bell) and "Max Items Shown".

EXAMPLE: a green badge that goes grey when empty — "Counter Background Color" = 2e7d32, "Counter Text Color" = ffffff, "Counter Background (at 0)" = 555555. Rename "Modal Heading" to "Your Alerts".

TIPS:

  • The badge only reflects what is NEW since last open, so a low or zero badge is normal for an active member who checks often.
  • The "(at 0)" colors let the badge fade to a calm look when there is nothing to see, instead of a loud red zero.
  • Turn "Include Personal Messages" Off if you want the bell to be notifications-only.

FEATURE 6 — WELCOME / AUTH PANEL (STYLING & CSS TAB)

WHAT IT IS: A small floating, MOVABLE panel (top-right by default) that shows a greeting plus the right auth links: a "Logout" link for logged-in members, or "Login" and "Register" links for guests. The notification bell sits on its left.

WHICH TAB: "Styling & CSS", the "Welcome / Auth Panel" section.

WHY THE LOGIN/LOGOUT STAYS VALID: the panel RE-USES ProBoards' own login, logout and register links (it re-homes them rather than inventing new ones). This matters because ProBoards' logout link carries a security token — by reusing the real link, the logout always stays correct.

The settings

  • "Show Welcome Message" — On (default) shows the greeting text; Off removes just the greeting (members still get the bell + Logout, guests still get Login | Register).
  • "Member Message" — the greeting for logged-in members. Use the token {name} where the username should appear. Blank = "Welcome, username."
  • "Guest Message" — the greeting shown to guests. Blank = "Welcome, Guest."
  • "Message Font Size" — greeting text size, e.g. "14px". Blank = nav font size.
  • "Panel Background" — the panel's fill color. Blank = nav-button background.
  • "Background Opacity" — 0–100 (100 = solid); only applies when a Panel Background is set. Blank = 100%.
  • "Text Color" — greeting text color. Blank = nav-button text.
  • "Auth Link Color" — color of the Login / Logout / Register links. Blank = the greeting Text Color above (so the links are always visible).
  • "Border Color" — panel outline color. Blank = nav-button border.
  • "Border Width" — outline thickness, e.g. "1px". Blank = nav-button border width.
  • "Corner Radius" — how rounded the panel is, e.g. "8px". Blank = nav corner radius.
  • "Padding (box size)" — padding around the whole panel; sets its overall size. Blank = 6px 12px.
  • "Horizontal Position" — distance from the RIGHT edge, in px (a bare number is px; a negative number pushes it further right). Default 0.
  • "Vertical Position" — distance ABOVE the nav, in px (positive = higher, up into the header; negative = down toward the nav). Default 0. If your theme's header is turned off and the panel sits too high, use a NEGATIVE value to bring it down.

Step by step, example, tips — welcome panel

  1. In "Styling & CSS → Welcome / Auth Panel", leave "Show Welcome Message" On (or turn it Off to keep only the links).
  2. Set "Member Message" using {name}, e.g. "Hi {name}!", and "Guest Message", e.g. "Welcome, guest — please sign in.".
  3. Style the panel with the color, border, radius and padding fields (or leave them blank to inherit the nav look).
  4. If the panel is not where you want it, nudge it with "Horizontal Position" and "Vertical Position".

EXAMPLE: a translucent card that greets members by name — "Member Message" = "Welcome back, {name}", "Panel Background" = 000000, "Background Opacity" = 40, "Corner Radius" = 10px. Move it in a touch with "Horizontal Position" = 20.

TIPS:

  • {name} only makes sense in the Member Message (guests have no username).
  • Because these are ProBoards' real auth links, do not worry about the logout token — it is handled for you.
  • The two Position fields MOVE the floating panel; if it overlaps your header or logo, adjust them (remember negative Vertical brings it down when the header is hidden).

FEATURE 7 — OTHER NAV-BAR ELEMENTS (PLACEMENT) (STYLING & CSS TAB)

WHAT IT IS: A single setting that decides what to do with items that OTHER plugins add into the nav bar (for example, a button some third-party plugin injects). BNB never styles those items; it only stops the layout from shoving them to the far left, and can optionally relocate them.

WHICH TAB: "Styling & CSS", the "Other Nav-bar Elements" section, the "Placement" setting.

"Placement" options:

  • "Leave in place" (default) — only prevents the layout from dragging those items to the far left; otherwise leaves them where they are.
  • "Move to row 2 (with search/bell)" — relocates them onto the second row alongside the search box and bell.
  • "Move to row 1 (with the nav)" — relocates them onto the main nav row.
  • "Move to new row" — puts them on a fresh row of their own.

EXAMPLE: another plugin adds a "Shop" button that lands awkwardly. Set "Placement" to "Move to row 2 (with search/bell)" to tuck it neatly next to the search box.

TIP: if third-party buttons look fine where they are, just leave this on the default. Only change it if their position bothers you.

FEATURE 8 — BREADCRUMB / NAVIGATION-TREE CONTROL (STYLING & CSS TAB)

WHAT IT IS: Control over ProBoards' built-in breadcrumb (the "navigation tree" line like Home » Board » Thread) — where it shows and where it sits.

WHICH TAB: "Styling & CSS", in the "Other Nav-bar Elements" area (the three "Breadcrumb:" settings).

  • "Breadcrumb: Show On" — where the breadcrumb appears: "All pages" (default), "Board & thread pages", or "Off".
  • "Breadcrumb: Specific Pages" — a box for extra page URLs or paths (like /shop), one per line. These are ADDED to "Board & thread pages". A path matches that page AND anything under it. Special case: when "Show On" is set to "Off", this box OVERRIDES to show the breadcrumb ONLY on the pages you list here (and an empty box with Off = hidden everywhere).
  • "Breadcrumb: Position" — where it sits when shown: "Directly above the forum content" (default) or "Leave where ProBoards puts it".

EXAMPLE: You only want the breadcrumb on board/thread pages plus your custom /shop pages. Set "Breadcrumb: Show On" = "Board & thread pages", and in "Breadcrumb: Specific Pages" type:
/shop
Because a path matches everything beneath it, /shop also covers /shop/item/123.

TIP: to hide the breadcrumb everywhere EXCEPT a few pages, set "Show On" = Off and list ONLY those pages in the Specific Pages box.

FEATURE 9 — CUSTOM CSS (STYLING & CSS TAB)

WHAT IT IS: A box for your own raw CSS. It is injected LAST — after all of the plugin's own styles — so anything you put here overrides everything else. This is the escape hatch for fine-tuning placement or appearance that the settings do not cover.

WHICH TAB: "Styling & CSS", the "Custom CSS" section at the very bottom.

Handy selectors the plugin documents for you (use these to target parts of the nav):

  • #hbnav-row2 — the whole second row.
  • .hbnav-row2-right — the right-hand cluster on row 2.
  • .hbnav-search — the search bar.
  • .hbnav-bell — the notification bell.
  • .hbnav-auth — the auth links.
  • .hbnav-extra — items other plugins added.
  • #welcome — the welcome panel.
  • #hbnav-mount — the plugin's mount point.

(The Setup Instructions tab also lists #navigation-menu and #hbnav-mount.)

EXAMPLE: nudge the welcome panel down a little regardless of other settings —
#welcome { margin-top: 6px; }

TIPS:

  • Because Custom CSS wins over everything, it is the right place to fix a stubborn detail — but use it sparingly.
  • Enter real CSS here (this box is CSS, not the plain-English settings), so normal CSS syntax and the "#" in hex colors are fine here — the "no #" rule only applies to the color PICKER fields elsewhere.
  • Leave it blank if you do not need it.

FEATURE 10 — SCROLL BUTTONS (OTHER FEATURES TAB)

WHAT IT IS: Two floating buttons pinned to the left or right gutter of the page and stacked one above the other, vertically centred. One smooth-scrolls to the TOP of the page, the other to the BOTTOM. They are OFF by default.

WHICH TAB: "Other Features", the "Scroll Buttons (Top / Bottom of Page)" section.

IMPORTANT COLOR NOTE: unlike the main nav pickers, these color fields apply EVEN in "Match Currency System" mode. Left unstyled the buttons use the same colors as the rest of the nav (and follow the Currency System / CS Extras button theme), but any color you set here overrides that for this one button set.

The settings

  • "Enable Scroll Buttons" — master On/Off. Default Off.
  • "Location" — which gutter (side): "Right" (default) or "Left".
  • "Alignment in Gutter" — how the stacked buttons align within the gutter: Left, Center, or Right. Blank follows the gutter side (Right gutter hugs right, Left gutter hugs left).
  • "Font Size" — e.g. "14px". Blank = the nav button font size.
  • "Text Alignment" — how the label sits inside the button: Left, Center (default), or Right.
  • "Top Button Text" — what the top button says. Blank = "▲ Top".
  • "Bottom Button Text" — what the bottom button says. Blank = "▼ Bottom".
  • "Background Color" — button fill. Blank = the nav button background (which follows Currency System / CS Extras).
  • "Background Opacity" — 0–100 (100 = solid). Blank = 100%.
  • "Text Color" — label color. Blank = nav button text color.
  • "Text Opacity" — 0–100. Blank = 100%.
  • "Border Color" — border color. Blank = nav button border color.
  • "Border Width" — e.g. "1px". Blank = nav button border width.
  • "Border Opacity" — 0–100. Blank = 100%.
  • "Corner Radius" — e.g. "8px". Blank = nav button radius.
  • "Padding" — e.g. "8px 12px". Blank = nav button padding.

Sub-section — Scroll Buttons: Hover Colors (optional)

  • "Hover Background Color" — fill on hover. Blank = same as resting background (no change). Uses the same Background Opacity as the resting state.
  • "Hover Text Color" — label color on hover. Blank = same as resting text color. Uses the same Text Opacity.
  • "Hover Border Color" — border color on hover. Blank = same as resting border color. Uses the same Border Opacity.

Step by step, example, tips — scroll buttons

  1. On the "Other Features" tab, set "Enable Scroll Buttons" to On.
  2. Choose the "Location" gutter (Right or Left) and, if you like, an "Alignment in Gutter".
  3. Optionally reword "Top Button Text" / "Bottom Button Text" and set a "Font Size" / "Text Alignment".
  4. Style the resting colors, then (optionally) the three Hover Colors.

EXAMPLE: subtle round buttons on the right — "Enable Scroll Buttons" = On, "Location" = Right, "Corner Radius" = 20px, "Background Color" = 222222, "Background Opacity" = 70, "Hover Background Color" = 000000.

TIPS:

  • These pickers work even in "Match Currency System" mode, so this is one place you CAN hand-set colors regardless of theme.
  • Leave a Hover color blank and that property simply does not change on hover.
  • The default labels use small triangle glyphs (▲ / ▼); replace them with your own words if you prefer plain text.

FEATURE 11 — HEADER & LOGO ADJUSTMENTS (OTHER FEATURES TAB)

WHAT IT IS: A section to restyle OR fully replace your forum's top banner (the header) and its logo. It has a MASTER TOGGLE that is OFF by default — nothing here does anything until you turn it on. Every field is optional; a blank field keeps whatever your theme already does.

WHICH TAB: "Other Features", the "Header & Logo Adjustments" section.

FIRST STEP ALWAYS: set "Enable Header & Logo Adjustments" to On. While it is Off, none of the header/logo fields below have any effect.

Header (top banner) options

The header is the wide banner strip at the very top of the forum. Its background is your theme's texture unless you set a Header Image.

  • "Hide Header" — remove the banner entirely. Default Off.
  • "Header Image URL" — a custom banner image that replaces the theme texture. Blank = keep the theme background.
  • "Alignment" — horizontal position of the header image: Keep theme (default), Left, Center, or Right.
  • "Image Fill" — how the image fills the banner: Keep theme, Tile / Repeat, Cover (fills and crops), Contain (fits the whole image), or Stretch (distorts to fill).
  • "Resize to Fit Screen" — scale the image to the forum width without cropping or tiling (this overrides "Image Fill"). Default Off.
  • "Height" — banner height, e.g. "120px". Blank = theme height.
  • "Padding" — inner spacing, e.g. "0px 20px". Blank = theme default.
  • "Background Color" — solid color behind the header image. Blank = theme background color.
  • "Background Color Opacity" — 0–100; only applies when a Background Color is set. Blank = 100%.
  • "Header Opacity" — fades the WHOLE header (image + logo together), 0–100. Blank = 100%.
  • "Inherit Extras Panel Border" — On makes the header borrow the Currency System Extras PANEL border in full (its color, width AND corner radius), so it tracks the CS theme and IGNORES the three border fields below. Off uses those fields. Default Off.
  • "Border Color" — header border color (used when Inherit is Off). Blank = no border.
  • "Border Width" — e.g. "1px". Blank = no border.
  • "Border Opacity" — 0–100; only applies when a Border Color is set. Blank = 100%.
  • "Corner Radius" — e.g. "8px" (used when Inherit is Off). Blank = square.
  • "Drop Shadow" — add a soft shadow under the header. Default Off.

Logo options

The logo is your forum name as text by default, or a logo image if you set one. Note: "Image Fill", "Max Width/Height" and "Resize" only apply to a logo IMAGE; alignment, opacity, border, hide and link apply either way.

  • "Hide Logo" — remove the logo. Default Off.
  • "Logo Image URL" — a custom image that replaces the text/logo. Blank = keep the theme's logo.
  • "Logo Link URL" — where clicking the logo goes. Blank = keep the theme's link (usually the forum home).
  • "Alignment" — horizontal position within the header: Keep theme (default), Left, Center, or Right.
  • "Image Fill" — how a logo IMAGE fills its box: Keep theme, Cover, Contain, Fill, or Original.
  • "Resize to Fit Screen" — let a logo image shrink on narrow screens. Default Off.
  • "Max Width" — e.g. "300px". Blank = natural size.
  • "Max Height" — e.g. "80px". Blank = natural size.
  • "Padding" — inner spacing, e.g. "4px 8px". Blank = theme default.
  • "Logo Opacity" — 0–100. Blank = 100%.
  • "Inherit Extras Panel Border" — On borrows the Currency System Extras panel border in full (color, width AND radius) and ignores the three border fields below; Off uses them. Default Off.
  • "Border Color" — logo border color (used when Inherit is Off; drawn around a logo image). Blank = no border.
  • "Border Width" — e.g. "1px". Blank = no border.
  • "Border Opacity" — 0–100; only when a Border Color is set. Blank = 100%.
  • "Corner Radius" — e.g. "8px" (used when Inherit is Off). Blank = square.
  • "Drop Shadow" — add a soft shadow under the logo. Default Off.

Step by step, example, tips — header & logo

  1. On the "Other Features" tab, set "Enable Header & Logo Adjustments" to On (nothing works until you do).
  2. For the banner: either "Hide Header", or set a "Header Image URL" plus "Image Fill"/"Height"/"Alignment" to taste.
  3. For the logo: either "Hide Logo", or set a "Logo Image URL", a "Max Width"/"Max Height", and "Alignment".
  4. Use the border, radius, opacity and "Drop Shadow" fields to finish the look. Consider "Inherit Extras Panel Border" if you run the Currency System and want borders to match it.

EXAMPLE: replace the banner with your own artwork and shrink the logo — "Enable Header & Logo Adjustments" = On, "Header Image URL" = https://example.com/banner.png, "Image Fill" = Cover, "Height" = 160px, "Logo Image URL" = https://example.com/logo.png, "Max Height" = 70px, "Alignment" (logo) = Left.

TIPS:

  • Nothing in this section takes effect while the master toggle is Off — check it first if your changes seem ignored.
  • "Resize to Fit Screen" (header) overrides "Image Fill", so set one or the other intentionally.
  • "Header Opacity" fades the image AND logo together; to fade only the logo use "Logo Opacity".
  • The "Inherit Extras Panel Border" switches take over color, width AND radius — while On, the individual border fields beneath them are ignored.

QUICK REFERENCE — WHICH TAB HOLDS WHAT

  • "Nav Bar" tab: Main Nav Bar Links, Sub Menu Links, Sub-sub Links (build the menu).
  • "Other Features" tab: Scroll Buttons; Header & Logo Adjustments.
  • "Styling & CSS" tab: Color Theme; Welcome / Auth Panel; Notification Bell; Menu Styling (Layout & Sizing, Main, Sub, Sub-sub); Search Bar; Other Nav-bar Elements (placement + breadcrumb); Custom CSS.
  • "Setup Instructions" tab: the short quick-start; nothing to fill in.

REMEMBER THE CROSS-CUTTING RULES:

  • Default Color Theme is "Match Currency System" — in that mode the nav color pickers are ignored; switch to "Dark" or "Light" to hand-pick colors.
  • Color fields: hex WITHOUT the "#".
  • Size / width / radius / offset fields: a bare number means pixels.
  • Opacity fields: 0 to 100.
  • Scroll Button colors work even in "Match Currency System" mode.
  • Header & Logo Adjustments do nothing until their master toggle is On.
  • Sub and Sub-sub links attach to a parent by an EXACT, case-sensitive match of the parent's "Link Text" in the child's "Parent Link Name".
