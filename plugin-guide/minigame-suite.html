Overview

The Minigame Suite adds place-anywhere mini-games that award currency, items, and temporary buffs — always paying out through the Currency System, never touching the economy directly.

You build a game from three pieces: a Stage (the scene or canvas), a Gacha instance (the game placed on it, with its trigger, content, and rules), and a weighted Loot Table (the prizes). Then you drop it on any page. Games can be free to play or cost an offering of currency and items, with an over-offer luck bonus that tilts the odds toward rarer loot. Buffs give temporary account-wide boosts, and Post Drops give members a passive chance at loot whenever they post.

Load order: Currency System → Currency System Extras (optional) → Minigame Suite.

Instruction Manual

The Setup Instructions inside the plugin’s own settings are a quick-start checklist. This is the full, plain-English walkthrough of every feature.

This manual explains EVERY feature of the CS Minigame Suite (MS) and walks you through building a game from scratch, step by step. It assumes you have never used the plugin and are not technical — every button and box is spelled out.

MS is an add-on to the Currency System (CS). It adds mini-games and interactive scenes to your forum that award your members currency, items, and temporary buffs. Think of things like a wishing well people toss coins into for a random prize, a gumball machine, a treasure chest, a vending NPC, or a hidden "click me" surprise tucked into a page.

EVERYTHING you configure lives on the tabs (pages) of THIS plugin's settings. As you read, you will move between these tabs: "Setup Instructions", "General Settings", "Game-Specific Settings", "Game Modal Templates", "Game Staging", "Gacha Games", "Styling Overrides", "Buffs", and "Loot Tables". This manual complements the built-in "Setup Instructions" tab (a quick-start on load order and placement); the odds, luck, and offering math are all covered here (see "Odds, Luck & Offerings" near the end).

READ FIRST - TERMINOLOGY

A few words show up a lot, and they do NOT all mean the same thing. Here is what each one is:

  • "Gacha" — the KIND of game: a player offers or turns something in and gets a random reward. This is the neutral name for it, and the one used in the tab names (the "Gacha Games" tab).
  • "Instance" — ONE built version of a gacha game: its own trigger, art, rules and loot. You can build many instances, each different, and place them wherever you like.
  • "Scene" — the STAGE a game is hosted on: the shared canvas / background that one or more instances sit on. "Scene" and "Stage" mean the same thing — you build them on the "Game Staging" tab, and "scene" is the word used in the placeholder code you paste onto a page (class="mgs-scene").

Put simply: a SCENE (stage) is the place; an INSTANCE is one gacha game placed on that scene; and "gacha" is the kind of game an instance is. One scene can hold several instances.

HOW MS FITS WITH THE CURRENCY SYSTEM

MS cannot run on its own. It is a companion to the Currency System (CS) plugin, which owns your forum's economy — the currency, the item shop, members' wallets and inventories, and the rarity ladder. MS never touches the economy directly. When a game pays out, MS asks the Currency System to do it. This is why the two plugins must be installed together, and in the right order.

LOAD ORDER (the #1 setup mistake)

The Currency System MUST load ABOVE the Minigame Suite in your forum's Plugins list. Plugins load top to bottom, so if MS loads first it cannot find the economy and it simply fails — usually with nothing appearing at all.

  1. In your ProBoards admin area, open the Plugins page (the list of installed plugins).
  2. Find "Currency System" and "CS Minigame Suite" in the list.
  3. Drag the Currency System so it sits ABOVE the Minigame Suite.
  4. Save. This is also stated on the plugin's "Setup Instructions" tab.

WHAT MS RELIES ON THE CURRENCY SYSTEM FOR

  • Item ids — every item you hand out as loot is a Currency System item; you reference it by its item id.
  • Item names and icons — MS pulls these automatically from the item id, so you never re-type them.
  • Item sell prices — when a player offers items to play a game, each item is valued at its Currency System sell price.
  • The rarity ladder — the ranks (e.g. plentiful, common, uncommon, rare, very rare, legendary) that luck uses to bias rolls, and the colors used for the rarity glow.
  • The wallet and payout — winnings are added to the member's balance by the Currency System.

THE BUILD MODEL — THREE LINKED PIECES

This is the single most important idea in the whole plugin. One game is built from THREE pieces that live on THREE different tabs. You build them in order and link them together with ids (short nicknames you make up).

  1. A STAGE (built on the "Game Staging" tab) = the CANVAS the game sits on. It is either a full-scene background picture (a drawn town, a temple room, a forest) that is defined ONCE and shared by every game placed on it, OR a "bare / frameless" stage that shows nothing but the trigger itself (used for hidden easter-egg triggers you can drop inline anywhere). Each stage has a unique Stage ID you choose.
  1. A GACHA INSTANCE (built on the "Gacha Games" tab) = ONE game placed on a stage. It carries its trigger and where the trigger sits, its content (the portrait, the title, the prompt, the button wording), and its gameplay rules (cooldown, daily limit, minimum offering, luck). Each has a unique Instance ID you choose.
  1. A LOOT TABLE (built on the "Loot Tables" tab) = the PRIZES, written as weighted rows that are keyed to an instance id. Each row is one possible outcome and how likely it is.

After those three pieces exist, you PLACE the game on your forum by pasting a small snippet of code where you want it to appear.

HOW YOU PLACE A GAME ON A PAGE

Paste this placeholder wherever the game should show — a page, a widget, a post template, a board description, anywhere HTML is allowed:

<div class="mgs-scene" data-scene="ID"></div>

Replace ID with either:

  • a STAGE ID — renders that stage's background once, PLUS every game placed on that stage (this is how a "hub" or "town" with several games appears together), or
  • an INSTANCE ID — renders that ONE game on its own.

Games appear ONLY where you paste this placeholder AND only after you have built the instance and given it a loot table. Nothing shows up automatically. There is exactly ONE exception: Post Drops, described later, which is passive and has a simple on/off switch because it happens by itself whenever a member posts.

NOTE — if you place a scene on a brand-new Custom Page, remember that a new Custom Page is not on your forum's menu yet, so members cannot reach it until you add a navigation link to that page (your forum's menu editor, or the Better Nav Bar "Nav Bar" tab). Scenes you drop onto an existing page, board description, or widget are already reachable.

FULL WALKTHROUGH — BUILD A "WISHING WELL" FROM SCRATCH

Follow this all the way through once and the whole plugin will click. We will build a Wishing Well that lives in a town scene, costs 10 coins to play, and can drop a handful of coins or, rarely, a shiny gem. We will invent these nicknames (ids) as we go: the stage is "town", the game is "wishing_well", and the gem item already exists in your Currency System with the id "gem". Your currency here is called Coins.

STEP 1 — BUILD THE STAGE (Game Staging tab)

  1. Open the "Game Staging" tab.
  2. Under "Game Stages", click to add a new row.
  3. Stage ID (stg_id): type town
  4. Frameless / Bare (stg_bare): leave on "No (normal stage)" — we want a real backdrop.
  5. Show Countdown Timers (stg_countdown): leave on "Yes".
  6. Background Image URL (stg_bg): paste the web address of your town artwork.
  7. Background Size (stg_bg_fit): choose "Fill the stage width" for a big drawn scene.
  8. Background Opacity % (stg_bg_opacity): leave 100.
  9. Border Color / Border Width / Corner Radius: optional frame — try Border Width 2 and Corner Radius 12 for a soft framed look, or leave them 0.
  10. Save. The stage "town" now exists as an empty canvas.

STEP 2 — BUILD THE GAME ON THAT STAGE (Gacha Games tab)

  1. Open the "Gacha Games" tab.
  2. Under "Gacha instances", add a new row.
  3. Instance ID (gc_id): type wishing_well
  4. Stage (gc_stage): type town (this links the game onto the stage you just made).
  5. Game Title (gc_name): type Wishing Well
  6. Sub-Header / Prompt Text (gc_offer_header): type Toss in a coin and make a wish...
  7. Minimum Offering (gc_min_offering): type 10 (this makes it cost 10 coins and opens an offering box when clicked).
  8. "Play" Button Text (gc_button_text): type Make a wish
  9. Button Type (gc_trigger_text): paste the web address of a well image to make the well itself the clickable trigger, OR type a word like Wishing Well to show a labeled button instead.
  10. Position (gc_pos): choose Center (or Left/Right).
  11. Trigger Offset & Size (gc_offset): optional; try 0, 10, 25% to nudge it down a touch and set its size to 25% of the scene.
  12. Reward Popup Title (gc_title): optional; blank uses the Game Title.
  13. Save. The game exists but has NO prizes yet, so it will not pay out.

STEP 3 — GIVE IT PRIZES (Loot Tables tab)

  1. Open the "Loot Tables" tab.
  2. Under "Loot outcomes", add three rows, all with "Applies to" set to wishing_well :

Row A — Reward type: Currency; Amount/quantity: 5-15; Weight: 80.
Row B — Reward type: Currency; Amount/quantity: 40; Weight: 19.
Row C — Reward type: Item; Item ID(s): gem; Amount/quantity: 1; Weight: 1.

  1. Save. The weights are 80 + 19 + 1 = 100, so a play gives 5-15 coins 80% of the time, 40 coins 19% of the time, and a gem 1% of the time.

STEP 4 — PLACE IT ON THE FORUM

  1. Decide where the town should appear — say, a page or a widget.
  2. Paste: <div class="mgs-scene" data-scene="town"></div>
  3. Because "town" is a STAGE id, this draws the town backdrop plus the Wishing Well (and any other games you later add to the town stage).
  4. If instead you wanted ONLY the well with no backdrop somewhere, you would paste data-scene="wishing_well" (the instance id).
  5. Save the page and view it as a normal member. Click the well: an offering box opens asking for at least 10 coins; confirm, and the reward popup reveals the prize. Done.

GAME STAGING TAB — EVERY FIELD

What it is: the tab where you build STAGES — the canvases your games sit on. A stage is defined once and can hold several games. Reach it by opening the "Game Staging" tab; add rows under "Game Stages".

A "hub" or "town" is simply one stage that several instances are placed on. You build the stage here once, then on the Gacha Games tab you set each game's "Stage" field to this stage's id. Placing the stage id renders the backdrop plus all its games together.

THE FIELDS

  • Stage ID (stg_id): the unique nickname for this canvas, e.g. town or altar_room. You will type this same id into each game's "Stage" field, and into the placeholder when you place the whole scene. Keep it short, lowercase, no spaces.
  • Frameless / Bare (stg_bare): "No (normal stage)" gives a real canvas with background and frame. "Yes (bare triggers only)" renders ONLY the trigger(s) — no background, box, border, frame, or padding. Use Bare for a hidden "easter-egg" trigger you drop inline in the middle of a page or post, where you want just a clickable thing and nothing around it. When Bare is Yes, the background and frame fields below are ignored.
  • Show Countdown Timers (stg_countdown): "Yes" shows a "Ready in H:MM:SS" label on any trigger that is locked by a cooldown or daily limit. "No" still dims a locked trigger but hides the timer text. Default Yes.
  • Background Image URL (stg_bg): the full-scene backdrop, posted ONCE here and shared by every game on this stage. Paste a web address. Leave blank for a trigger-only stage (a stage with no backdrop but still framed).
  • Background Size (stg_bg_fit): "Fill the stage width" stretches the image to the full stage width (a small image is enlarged). "Natural size (never upscale)" shows the image at its own size, centered, capped to the stage width but never enlarged. Use Fill for big drawn scenes; use Natural for pixel art you do not want blown up.
  • Background Opacity % (stg_bg_opacity): 0-100, how solid the backdrop is. Default 100 (fully visible). Lower it to fade the scene.
  • Border Color (stg_border_color): the frame color around the stage. Blank uses your theme's accent color.
  • Border Width px (stg_border_width): thickness of the frame. 0 = no frame.
  • Corner Radius px (stg_radius): rounds the stage corners. 0 = square corners; try 12 for softly rounded.

EXAMPLE — A TOWN HUB

Stage ID: town; Frameless: No; Show Countdown Timers: Yes; Background Image URL: your town art; Background Size: Fill the stage width; Opacity: 100; Border Width: 2; Corner Radius: 12. Later you add three games (a well, a shop NPC, a fountain) all with Stage = town, and one placeholder data-scene="town" shows the whole town with all three.

TIPS & GOTCHAS

  • A Bare stage is the trick for hidden triggers: build a Bare stage, place one instance on it, and drop that instance's placeholder inline in a post — members see only your clickable image, no box.
  • If you place a whole stage but see the backdrop with no games, you have not yet placed any instances on that stage (check each game's "Stage" field), or those games have no loot table.
  • The "Card Scene" (a game with no stage) ignores the stage background entirely.

GACHA GAMES TAB — EVERY FIELD

What it is: the tab where you build one GAME (instance) and place it on a stage. Open the "Gacha Games" tab and add rows under "Gacha instances". Each row is one game. The fields below are grouped by what they do: IDENTITY & PLACEMENT, CONTENT, and GAMEPLAY. (The look of the pop-up windows is inherited from the Game Modal Templates tab and can be fine-tuned per game on Styling Overrides — covered later.)

GROUP A — IDENTITY & PLACEMENT

  • Instance ID (gc_id): the unique nickname for this game, e.g. altar or gumball. This is the id you use in a placeholder to render just this game, and the id you key loot rows to. Short, lowercase, no spaces.
  • Stage (gc_stage): the Stage ID (from the Game Staging tab) this game is placed on. Leave blank to make the game a standalone card that floats on the page by itself with no shared backdrop.
  • Position (gc_pos): where the trigger sits on the stage — Center, Left, or Right. Default Center. Use Left/Right to arrange several games across one town scene.
  • Trigger Offset & Size (gc_offset): three comma-separated values written as X, Y, Size . X nudges left/right, Y nudges up/down (in px, or a % of the scene; + or - allowed), and Size sets the trigger image size (a % of the scene, or px). Leave any part blank to inherit. Example: 10, -5, 20% moves it slightly right, slightly up, and sizes it to 20% of the scene.
  • Button Type (gc_trigger_text): how the player opens the game. If you paste an IMAGE web address here, the trigger becomes that clickable image (e.g. the well art itself). If you type any other TEXT, the trigger is a button with that text as its label. Blank uses the default interact-button text.
  • Hover Outline Color (gc_hover_color): the color of the ring that appears when a player hovers the trigger. SETTING a color turns the hover highlight ON; leaving it blank means no highlight. Supports 8-digit hex if you want a see-through ring.
  • Hover Outline Width px (gc_hover_width): thickness of that hover ring. Blank = 3.

GROUP B — CONTENT (words, portrait, companion)

  • Game Title (gc_name): the game's name. It appears as the header of the transaction/offering window, and is used in the reward popup and in the Currency System history reason.
  • Sub-Header / Prompt Text (gc_offer_header): an optional line shown under the title inside the offering window, e.g. "Toss in a coin and make a wish...". Blank = no prompt line.
  • "Play" Button Text (gc_button_text): the label on the ACTION button inside the offering / free-play window — the button that actually commits the play. Default "Make an offering".
  • Reward Popup Title (gc_title): the title shown on the reward reveal popup. Blank uses the Game Title.
  • Reward Popup Message (gc_reward_msg): optional override, for THIS game only, of the lead-in label shown above the reward. Blank uses the global one set on the Game Modal Templates tab. It is plain text (e.g. "You received:") — the items, buffs, and currency are listed automatically beneath it. (See the Reward Reveal section below.)
  • Companion Box Title (gc_companion_name): a short title on the optional COMPANION card — its own header, separate from the Game Title. The companion is a side panel (like a character talking to you) that appears beside the modal automatically whenever it has ANY content (this title, a companion image, body text, or footer). Blank = no companion header.
  • Companion Image URL (gc_companion_image): the portrait / art shown on the companion card (separate from the stage background). Blank = no image and no empty box.
  • Body Text (gc_flavor): the companion panel's HEADER text, shown at the TOP of the companion, above the portrait. Blank = none. (Despite the label "Body Text", it sits at the top of the companion card.)
  • Footer Text (gc_footer): small text at the foot of the companion card. Blank = none.

The next four are per-game TRI-STATE toggles for the companion's bands. Each is "Inherit (template default)", "On", or "Off" — Inherit follows the Game Modal Templates default, On/Off force it for just this game:

  • Companion — Title Bar (gc_title_bar): the name band from Companion Box Title.
  • Companion — Panel Background (gc_companion_panel): On = a bordered panel behind the companion; Off = a bare floating portrait (its shadow hugs the image).
  • Companion — Header Background (gc_header_bg): the plate behind the companion header/flavor text.
  • Companion — Footer Background (gc_footer_bg): the plate behind the companion footer text.

GROUP C — GAMEPLAY (cost, limits, luck)

  • Cooldown Time in Minutes (gc_cooldown): minutes a player must wait between plays. 0 = no cooldown.
  • Cooldown Message (gc_msg_cooldown): the message shown while the game is on cooldown.
  • Show Cooldown Countdown (gc_show_countdown): Yes appends the remaining time to the cooldown message.
  • Daily Limit (gc_daily_limit): max plays per player per day. 0 = unlimited.
  • Daily-Limit Message (gc_msg_limit): the message shown once the daily limit is reached.
  • Reveal Suspense (gc_suspense): Yes plays a short "roll" animation before revealing the reward — a slot-machine icon cycle when the loot has item icons, otherwise a shaking "?" card. Respects reduced-motion settings. Default No.
  • Offering Accepts (gc_accepts): what the offering window accepts — Both, Currency only, or Items only. Items only hides the currency box. Default Both.
  • Minimum Offering (gc_min_offering): the required offering value in currency. 0 = FREE click-to-play (an instant loot roll, no offering window). Any value ABOVE 0 makes clicking open the offering window where the player must offer at least this much value.
  • Offering: Below-Minimum Message (gc_reject_msg): shown when the player's offering is worth less than the minimum.
  • Max Luck Bonus (gc_boost_max): the most extra "luck" a big over-offering can add to a single roll (approached but never reached). Luck biases the roll toward rarer items — same scale as the Luck buff. 0.25 = a gentle nudge, 1 = a strong nudge, 0 = off.
  • Half Max Luck Bonus Cost (gc_boost_half): how much a player must offer OVER the minimum to reach HALF of the max luck bonus. Lower = the bonus ramps up fast (steep curve); higher = it ramps up slowly.
  • Confirm Offer Message (gc_confirm_msg): the "are you sure?" text shown after the player taps Offer with a valid offering. Only appears when Minimum Offering is above 0. Tags: {offering} {value} {min} {currency} {symbol}.

EXAMPLE — A PAID ALTAR WITH LUCK

Instance ID: altar; Stage: altar_room; Game Title: Ancient Altar; Sub-Header: "Leave an offering for the spirits."; Minimum Offering: 50; Play Button Text: Offer; Max Luck Bonus: 1; Half Max Luck Bonus Cost: 100; Cooldown: 60; Cooldown Message: "The altar is resting."; Daily Limit: 5. A player who offers exactly 50 gets base odds; a player who offers 150 (100 over) gets half the max luck (L = 0.5), tilting the roll toward rarer items. See the "Odds, Luck & Offerings" section of this guide for the exact math.

TIPS & GOTCHAS

  • Minimum Offering = 0 is the big fork in behavior: 0 means one click plays instantly (great for a free "daily chest"); above 0 opens the offering window.
  • A game with no loot table pays nothing — always build its Loot Tables rows.
  • The companion panel only appears if you give it content; leaving all companion fields blank means no side panel at all.

WHAT A PLAYER SEES WHEN THEY PLAY

Understanding the runtime flow helps you set the fields sensibly.

  1. The trigger — the member sees the trigger you defined (an image or a labeled button) sitting on the stage. Hovering shows the hover ring (if you set a Hover Outline Color) and a tooltip with the game's name.

2a. FREE play (Minimum Offering = 0): clicking plays instantly — the loot rolls right away and the reward popup appears.

2b. PAID play (Minimum Offering above 0): clicking opens the OFFERING window. The player offers currency and/or items (depending on "Offering Accepts"). Items they add are valued at their Currency System sell price. The total offered must meet the minimum or it is rejected with your Below-Minimum Message. Offering MORE than the minimum grants a temporary luck bonus for that one roll (better odds of rarer prizes). The player taps the action button (your "Play" Button Text), sees the Confirm Offer Message, and confirms.

  1. Locked games — if the game is on cooldown or the player has hit the daily limit, the trigger DIMS and (if the stage's Show Countdown Timers is on) shows a live "Ready in H:MM:SS" countdown. The player cannot play until it clears.
  1. The reveal — if Reveal Suspense is on, a slot-reel or a shaking "?" plays first; then the reward reveal popup shows what they won (or a friendly "nothing" message).

LOOT TABLES TAB — PRIZES & WEIGHTS

What it is: the tab where you decide what each game can drop. Open the "Loot Tables" tab; add rows under "Loot outcomes". Loot lives HERE, not on the games themselves. Each row is ONE possible outcome, keyed to the game(s) it belongs to. A game's full loot table is every row that lists its id, pooled together — so you build up a table by adding many rows with the same id.

THE FIELDS (one row = one outcome)

  • Applies to (instance id / ids) (lt_ids): which game(s) can roll this outcome — the Instance ID from the Gacha Games tab. Comma-separate several to share one outcome across games, e.g. altar, gumball . The reserved id post_drops targets the passive Post Drops game.
  • Reward type (lt_type): what this outcome gives — Currency, Item, Buff, or Nothing. Only the fields for the chosen type are used.
  • Item ID(s) (lt_items): Item type only. The Currency System item id. A comma list (e.g. rusty_key, bronze_key ) rolls ONE of them at random. Name and icon come from the item id automatically.
  • Buff ID(s) (lt_buffs): Buff type only. The buff id from the Buffs tab. A comma list rolls one at random.
  • Buff level (lt_buff_level): Buff type only. Which strength tier to grant, from the buff's levels ladder. A single number like 2, or a range like 1-3 to roll one. Blank = 1 (clamps to the top tier).
  • Amount / quantity (min-max) (lt_range): for Currency, the amount awarded; for Item, how many. A range like 1-5 or a single fixed number like 10. Leave blank for Buff or Nothing.
  • Buff duration (min-max minutes) (lt_buff_dur): Buff type only. How long it lasts, in minutes — a range like 30-60 or a single number. Blank uses the Buffs-tab default duration.
  • Weight (lt_weight): the relative chance of this outcome versus the other rows for the same game. Higher = more likely. Blank = 1.
  • (Optional) A Reveal message can override this row's default popup text; a Nothing outcome with a blank message shows the default miss line "You received nothing this time...".

WEIGHT IS THE HEART OF IT — READ CAREFULLY

WEIGHT is RELATIVE. An outcome's chance = its weight DIVIDED BY the total of all weights for that game. If you make the weights for a game add up to 100, you can read each weight directly as a percentage.

WEIGHT IS NOT RARITY. This trips everyone up. The rarity tag on an item (common, legendary, etc.) does NOT control how often it drops — only its WEIGHT does. A "legendary"-tagged item with a big weight will drop constantly. To make something genuinely rare you must give it BOTH a small weight AND a high rarity tier. The rarity tier is used only to decide how strongly LUCK boosts that item (see the "Odds, Luck & Offerings" section of this guide); the weight decides the base odds.

WORKED EXAMPLE — A LOOT TABLE WITH PERCENTAGES

Game id: gumball. Four rows, all Applies to = gumball:

  1. Nothing — Weight 50.
  2. Currency — Amount 1-3 — Weight 35.
  3. Item — Item ID gumball_common — Amount 1 — Weight 14.
  4. Item — Item ID gumball_rare — Amount 1 — Weight 1.

Total weight = 50 + 35 + 14 + 1 = 100, so the odds read straight off: 50% nothing, 35% a few coins, 14% a common gumball, 1% the rare gumball. To make the rare truly special, tag gumball_rare as a high rarity in the Currency System AND keep its weight at 1 — small weight for rare odds, high rarity so luck lifts it a bit when players are lucky.

TIPS & GOTCHAS

  • You do not need weights to total 100 — they are relative — but making them total 100 makes the odds easy to read.
  • To let two games share the exact same prize pool, list both ids in "Applies to" (comma-separated) on each row.
  • Post Drops uses the reserved id post_drops — add rows with that id to fill its table.
  • An item id must exist in your Currency System, or the drop has nothing to show.

BUNDLE LOOT — GRANT SEVERAL THINGS AT ONCE

What it is: a normal loot row gives ONE thing. A BUNDLE is a single outcome that, when it lands, can hand out an item AND currency AND a buff together in one drop. It lives in the "BUNDLE LOOT" section further down the Loot Tables tab (under "Bundle outcomes").

How it works: a bundle has three boxes — Items, Currency, Buffs. Any box you fill in rolls INDEPENDENTLY every time the bundle drops. So one bundle drop can produce a potion (from the Items box) plus 20 coins (from the Currency box) plus a Luck buff (from the Buffs box). Leave a box blank to skip that reward type. Within its Items box a bundle picks ONE outcome by weight — but a single outcome can bundle several different items together (see "Granting multiple items" below).

Granting multiple items

There are two ways to hand out more than one item, and you can combine them:

  1. MORE OF ONE ITEM (a stack) — put a quantity or range in the item: (elixir 3, 100) gives 3 elixirs; (elixir 2-5, 100) gives 2 to 5.
  2. SEVERAL DIFFERENT ITEMS at once — list them in the SAME reward, separated by ";", each with its own quantity: (potion 1-2; herb 5-12, 80). Picking this one outcome grants 1-2 potions AND 5-12 herbs together.

To offer a random CHOICE between different item sets, make each set its own reward and let the box (or a group) pick one: (potion 1-2; herb 5-12, 80), (rock 5-10; stick 5-10, 20) — 80% the potion+herb pair, 20% the rock+stick pair.

Note: a plain list of rewards in a box is a weighted PICK-ONE, not a give-all — it is the ";" inside a single reward that bundles items together.

THE FIELDS

  • Applies to (instance id / ids) (bd_ids): which game(s) can roll this bundle — comma-separate to share; use post_drops for Post Drops. The whole bundle competes as ONE outcome in those games' pools.
  • Items (bd_items): the Items sub-table (a weighted tree, see below).
  • Currency (bd_currency): the Currency sub-table.
  • Buffs (bd_buffs): the Buffs sub-table.
  • Bundle weight (bd_weight): the relative chance of this whole bundle versus the game's other loot outcomes. Blank = 1.

THE TREE GRAMMAR (kept light)

Each box is a small weighted table. The game picks ONE outcome from it and grants what that outcome holds.

A REWARD is written in round brackets ( ), with its WEIGHT as the last number:

  • Currency — (amount, weight), e.g. (10-30, 100).
  • Buff — (id level, weight), e.g. (clover 1, 10) — a SPACE between the id and its level.
  • Item — (id qty, weight), e.g. (sword 1, 80) or (gem 1, 20) — a SPACE between the id and its quantity; qty can be a number or range (1-5), or left off for 1.
  • No prize — (nothing, weight).

To put SEVERAL ITEMS in one reward, separate them with a semicolon, each with its own quantity: (potion 1-2; herb 5-12, 80). If that outcome is picked, every item in it is granted together. (Currency and Buffs give one thing per outcome.)

A GROUP picks ONE outcome out of several. Write its weight FIRST, then a comma, then the outcomes. Curly { } is an outer group and square [ ] is a group nested inside it — both are the same "pick one", used only to nest choices inside choices.

Resolving works from the outside in: pick one child in the { } group, then one in the [ ] it led to, until you reach a round ( ) reward — curly → square → round. Weights are relative at each level (a choice's chance = its weight ÷ the total of its siblings).

SIMPLE BUNDLE EXAMPLE

Applies to: chest. Bundle weight: 5.

  • Items box: (potion 1-2; herb 5-12, 80), (gem 1, 20) — 80% a potion-and-herb pair, 20% a single gem.
  • Currency box: (10-30, 100) — always some coins, 10 to 30.
  • Buffs box: (nothing, 90), (clover 1, 10) — usually no buff, 10% a level-1 Lucky Charm.

When this bundle drops, the player gets coins for sure, one item (usually a potion), and occasionally a buff — all in a single reveal.

ITEM PLURALS — TIDY WORDING FOR STACKS

What it is: an optional small setting so reward text reads correctly for irregular plurals. It lives at the bottom of the Loot Tables tab as the "Item plurals (JSON map)" box, and applies to every game.

Why: when a player wins more than one of something, MS pluralizes the name. Regular names just get an "s" added automatically ("Common Potion" becomes "Common Potions"), so MOST items need nothing here. Only irregular plurals need listing.

How: it is a small JSON map keyed by the item's UNIQUE ID (the same id you use in loot tables, NOT the display name). The value is the full plural of the display name. Example:
{
"berry": "berries",
"loaf_of_bread": "loaves of bread"
}
Default is {} (none). If you have no irregular plurals, leave it as {}.

THE REWARD REVEAL POPUP (SHARED BY EVERY GAME)

What it is: the popup that reveals what a player won. It is shared by every game so the experience stays consistent. Its default look is themed from the Game Modal Templates tab (and can match the Currency System), and its default wording is set in one place.

HOW THE REWARD IS LAID OUT

The popup shows the reward in a fixed, readable order — you do NOT compose it by hand:

  1. Header title — the Reward Popup Title (or the game's name).
  2. A lead-in label — plain text like "You received:" (this is the customizable part, see below).
  3. The reward itself, laid out automatically:

• Every ITEM won shows as its own card (the same card look as the shop and inventory), with its quantity as a small "×N" chip in the card's corner. Cards simply sit in a row under the label — no words, commas, or punctuation between them.
• Any BUFF or CURRENCY won then appears on its OWN line beneath the cards. When there is more than one such line they are joined with grammar: earlier lines end in a comma and the last line starts with "and" and ends with "!". (A single buff or currency with nothing before it just ends in "!", no "and".)

Examples:

  • Two items only: the two cards, and nothing else — no "!".
  • Two items + a buff + currency:

[Potion ×2 card] [Herb card]
Clover for 30 minutes,
and 3 Coins ✦!

  • Currency only: a single line, "40 Coins ✦!".

CUSTOMIZING THE LEAD-IN LABEL

The only wording you set is the lead-in label above the reward. It is plain text — no tags to fill in, because the items, buffs, and currency are listed for you.

  • Global default: set it on the Game Modal Templates tab as "Reward Popup Message (gacha_reward_msg)". It defaults to "You received:".
  • Per game: any single game can override it with its own "Reward Popup Message (gc_reward_msg)" on the Gacha Games tab. Blank = use the global one.

Examples: "You received:", "Your loot:", "The spirits grant you...".

THE "NOTHING" RESULT

When an outcome is Nothing, the popup shows a fixed friendly miss message ("You received nothing this time...") if you left that row's message blank. Important difference: passive Post Drops stays SILENT on a nothing result (no popup interrupts a member who was just posting), while interactive plays (games the player clicked) always show something so the click never feels ignored.

REVEAL SUSPENSE & RARITY GLOW

  • Reveal Suspense (set per game) plays a short animation before the reveal — a slot-reel of item icons, or a shaking "?" card — then shows the prize. It honors reduced-motion accessibility settings.
  • Rarity glow: the won card can pulse a colored glow, bigger for rarer items. Turn it on with "Show rarity glow on rewards" on the General Settings tab (default Yes). The glow COLOR comes from the Currency System's rarity palette, with a built-in fallback palette, so the glow works even if the Currency System's rarity borders are turned off. (The static rarity border and card sizing for this popup are controlled in Currency System Extras, not here.)

BUFFS TAB — TEMPORARY REWARD BOOSTERS

What it is: a buff is a temporary, account-wide boost that makes OTHER games more rewarding for a while, then expires on its own. You DEFINE buffs on the "Buffs" tab, then hand them out as "Buff" outcomes in any game's loot table. The whole system has a master switch, "Enable Buffs", on the General Settings tab (default Yes). When Off, both the players' active-buffs HUD strip and the staff Buff Grant panel are hidden.

THE THREE EFFECTS

A buff has exactly one effect:

  • luck — biases loot rolls toward rarer items (same scale as over-offering luck).
  • currency_mult — boosts the currency a player wins.
  • qty_mult — boosts the size of item stacks a player wins.

THE BUFFS TAB FIELDS

At the top:

  • Default duration (minutes): how long a buff lasts when its loot drop does not set its own duration. Default 60.

Then the BUFF REGISTRY — one row per buff, defined like a shop item:

  • Name (buff_name): shown in reward popups via the {buff} tag.
  • ID (buff_id): the id that loot "Buff" outcomes reference (e.g. clover). Handled like an item id.
  • Effect (buff_effect): one of luck, currency_mult, qty_mult.
  • Levels (buff_levels): a comma list of strengths, weakest to strongest, e.g. 0.5, 0.7, 1.0 . A buff can come in several strengths; a loot drop's "level" number picks one (level 1 = the first value, level 2 = the second, and so on).
  • Duration (buff_duration): minutes; blank uses the Default duration above; a loot drop's own duration overrides both.
  • Description (buff_desc): for your own reference (and shown in the players' HUD guide).

WHAT THE LEVEL NUMBERS MEAN

What a level value MEANS depends on the effect:

  • Currency or Quantity buff: how much bigger the reward gets. 0.5 = +50%, 1.0 = double.
  • Luck buff: how strongly the odds tilt toward rarer items — bigger = luckier. (The exact luck math is on the "Odds, Luck & Offerings" section of this guide.)

The three buffs that ship as examples: "Lucky Charm" (id clover, luck, levels 0.5, 0.7, 1.0), "Fortune" (id fortune, currency_mult, levels 0.25, 0.5, 1.0), and "Hoarder" (id hoard, qty_mult, levels 0.5, 1.0).

STACKING RULES

  • Granting the SAME buff again EXTENDS its timer (the durations add up) and keeps the HIGHER level.
  • DIFFERENT buffs stack and run side by side, BUT for each effect only the STRONGEST active value applies (no compounding). So two currency buffs do not multiply together — the stronger one wins.

THE PLAYERS' ACTIVE-BUFFS HUD

Members see a small strip of their active buffs docked right next to the Currency System's wallet pill (to its left) in the HUD row. Each buff shows its name, its level (Lv), and the time left, plus a "?" that opens a short guide. It ticks down live and disappears when the buff expires. It is hidden entirely when Enable Buffs is Off.

THE STAFF BUFF GRANT PANEL

Staff get a Buff Grant panel that appears just under the Currency System's admin grant panel. From it, staff can grant a buff to a specific member or to everyone. Grants are delivered on the recipient's NEXT page load. Its header text is set by "Grant Panel Header" on the General Settings tab (blank = "Grant Buffs"). It is hidden when Enable Buffs is Off.

HANDING OUT A BUFF FROM LOOT

On the Loot Tables tab, add a row with Reward type = Buff, Buff ID(s) = the buff id (e.g. clover), Buff level = a number or range, and Buff duration = minutes or blank. Example: a game drops a level-2 Lucky Charm for 45 minutes — Buff ID(s): clover; Buff level: 2; Buff duration: 45; Weight: 5.

POST DROPS — THE ONE PASSIVE GAME

What it is: the only game that runs by itself. When a member makes a post, there is a chance they find a reward — no clicking, no trigger to place. Because it is passive, it is the one game with an on/off switch: "Enable Post Drops" on the General Settings tab (default No/off). Its odds and limits are set on the "Game-Specific Settings" tab under "POST DROPS", and its prizes come from Loot Tables rows keyed to the reserved id post_drops .

GAME-SPECIFIC SETTINGS FIELDS (POST DROPS)

  • Name (encounter_name): the display name for this game. Blank = "Post Drops".
  • Popup title (encounter_title): the heading on its reward popup. Blank = "You found something!".
  • Appearance rate (%) (encounter_rate): the chance a drop appears per post. Accepts partial percentages like 0.1. Range 0.001-100. Default 1 (one percent of posts).
  • Max per day (encounter_max_per_day): drops per member per day. 0 = unlimited. Default 10.
  • Boards (encounter_boards): pick the boards Post Drops can fire on. Leave blank for ALL boards.
  • Cooldown (minutes) (encounter_cooldown): minimum minutes between a member's drops. 0 = off.
  • Daily earning cap (encounter_earn_daily): max currency per member per day from Post Drops. 0 = unlimited.
  • Weekly earning cap (encounter_earn_weekly): max currency per member per week from Post Drops. 0 = unlimited.

ITS LOOT

Add rows on the Loot Tables tab with "Applies to" = post_drops. The plugin ships with a starter table: 70 weight nothing, 25 weight of 1-5 currency, 5 weight of 10 currency. Remember Post Drops stays SILENT on a nothing result so it never interrupts a poster.

EXAMPLE

Enable Post Drops: Yes; Name: Lucky Find; Popup title: You found something!; Appearance rate: 2; Max per day: 5; Boards: leave blank for all; Cooldown: 10; Daily earning cap: 100. Then loot rows keyed to post_drops decide what turns up.

GENERAL SETTINGS TAB — GLOBAL RULES & SHARED STYLING

What it is: the tab for forum-wide rules and shared look-and-feel. Open the "General Settings" tab. (The Enable Post Drops and Enable Buffs toggles here are covered in their own sections above.)

GLOBAL EARNING CAPS

  • Daily cap (all games) (cap_daily): the most currency a member can earn per DAY across ALL games combined. 0 = unlimited.
  • Weekly cap (all games) (cap_weekly): the same, per WEEK. 0 = unlimited.

These work alongside per-game caps (like Post Drops' own daily/weekly caps). THE TIGHTER LIMIT WINS — if the global daily cap is 100 and a game's own cap is 50, the member can earn at most 50 from that game.

OTHER (staff & bookkeeping)

  • Staff test mode (test_mode): when Yes, staff/admin accounts bypass caps and cooldowns so they can test games freely. Only affects staff. Default No. Turn it off before launch so your own testing does not skew things.
  • Debug mode (staff only) (debug_mode): when Yes, logs each game's activity to the browser console (press F12) for staff only — useful for troubleshooting. Players never see anything. Default No.
  • Log winnings to Currency System history (log_to_history): when Yes, records mini-game winnings in the Currency System transaction log. Default No.
  • Member groups that can earn (allowed_groups): only these groups earn from mini-games. Leave blank for everyone.

STYLING — MATCH CURRENCY SYSTEM

These toggles let each surface inherit the Currency System's theme so MS looks native. When a toggle is On (default), that surface borrows CS colors. IMPORTANT: matching only fills the BLANKS — any color you set yourself for that surface still wins. (This differs from Currency System Extras, where a blank field is what triggers inheritance; here matching is a straight on/off toggle and your explicit colors override it.)

  • Reward popup (match_cs_popup): the reward-reveal popup inherits CS background / heading / text colors. Default Yes.
  • Scene card (match_cs_gacha): the gacha scene card's text and accents inherit CS colors. Default Yes.
  • Buttons (all MS) (match_cs_buttons): MS action buttons inherit the CS button theme. Default Yes.
  • Buff grant panel (match_cs_buffpanel): the staff Buff Grant panel inherits CS panel styling. Default Yes.

STYLING — REWARD POPUP OVERRIDES

The reward popup is shared by all games. With its match toggle on it inherits CS theme; set any color below to use your own:

  • Show rarity glow on rewards (mgs_rarity_glow): pulse a rarity-colored glow around a won item, bigger for rarer items. Default Yes.
  • Popup background (reveal_bg), Popup title color (reveal_header_color), Popup text color (reveal_text_color): blank = inherit the popup theme; set a color to override.

STYLING — TOOLTIPS & BUFF PANEL HEADER

  • Tooltip look — one style for every hover tooltip in the suite. The tooltip TEXT is set automatically per thing (a buff shows its description, a trigger shows its game name), so you only set colors: Tooltip background (tip_bg; blank = the CS button color; supports 8-digit hex for transparency), Tooltip text color (tip_color; blank = the CS button text color), Tooltip background opacity % (tip_bg_opacity; 0-100, blank/100 = solid).
  • Grant Panel Header (buff_grant_header): the title at the top of the staff Buff Grant panel; blank = "Grant Buffs".

GAME MODAL TEMPLATES TAB — THE DEFAULT LOOK

What it is: the DEFAULT styling that EVERY gacha game inherits for its pop-up windows and companion panel. Set it once here and all games follow it; you only override per-game on the Styling Overrides tab when one game should differ. Open the "Game Modal Templates" tab.

KEY TIP: each styling field's label shows a var id in parentheses, e.g. "Button color (gacha_button_color)". That parenthesized id is what you copy into a Styling Override to change that one thing for one game. So this tab doubles as the reference list of override keys.

WHAT YOU CAN SET HERE

  • Reward Popup Message (gacha_reward_msg): the global lead-in label shown above the reward (see the Reward Reveal section). Plain text; default "You received:".
  • Companion card: whether there is a background panel behind the companion (gacha_companion_panel), the header/footer text color (gacha_companion_text_color) and alignment (gacha_companion_align).
  • Companion background image: a URL that fills the companion panel (gacha_bg_image), its opacity (gacha_bg_opacity), and how it fits — Cover or Contain (gacha_bg_fit).
  • Companion size & font: panel width (gacha_width), font color (gacha_font_color), font size (gacha_font_size).
  • Companion header & footer bands: show/color/opacity for the header band (gacha_header_plate, gacha_header_plate_color, gacha_header_plate_opacity) and the footer band (gacha_footer_plate, gacha_footer_plate_color, gacha_footer_plate_opacity).
  • Companion portrait sizing: max height (gacha_content_img_height), opacity (gacha_content_img_opacity), vertical offset up/down (gacha_content_offset).
  • The full BUTTON set for offer/claim/trigger buttons: color (gacha_button_color), text color (gacha_button_text_color), hover color (gacha_button_hover_color), hover text color (gacha_button_hover_text_color), border color (gacha_button_border_color), border width (gacha_button_border_width), corner radius (gacha_button_radius), padding (gacha_button_padding), font size (gacha_button_font_size), font family (gacha_button_font), finish — Flat/Gradient/Glossy/Chrome (gacha_button_finish), and an optional button image URL (gacha_button_image).
  • The TRIGGER BUTTON defaults (for games that use a labeled button as their trigger): trigger font size (gacha_trigger_font_size), padding (gacha_trigger_padding), opacity (gacha_trigger_opacity), font family (gacha_trigger_font).

TIPS & GOTCHAS

  • Beginners can leave this tab mostly alone — the defaults plus "Match Currency System" already look tidy.
  • To float just a portrait with no box behind it, set the companion panel off / border 0 / opacity 0 (here, or per game via an override).
  • Note each field's id (shown in parentheses on its label) starts with "gacha_" — copy that id into an override map to change it for just one game.

STYLING OVERRIDES TAB — PER-GAME TWEAKS

What it is: a place to restyle ONE game differently from the template, without touching the others. Open the "Styling Overrides" tab; add rows under "Styling overrides". Beginners can ignore this tab entirely and rely on the Game Modal Templates defaults — come back only when you want one specific game to look special.

HOW A ROW WORKS

Each row has two fields:

  • Instance ID (ov_id): which game (its gc_id from the Gacha Games tab) this override restyles.
  • Override map (ov_map): a small JSON map of var:value listing ONLY what changes. Read the exact var ids off the Game Modal Templates tab (the parenthesized ids). Everything you do not list falls back to the template, then to the Currency System theme.

Example — make only the game "altar" have a gold, slightly thicker border:
Instance ID: altar
Override map: {"gacha_border_color":"#c9a227","gacha_border_width":"3"}
Only altar changes; every other game stays on the template. Values may be numbers or quoted strings; colors take a hex value with or without a leading #; Yes/No band toggles take "yes" or "no". A row with broken JSON is skipped (that game keeps the template) and a warning is logged to the browser console.

READY-MADE COPY-PASTE TEMPLATES

The tab includes maps you can paste and then tweak, including:

  • "Floating companion" — just the portrait, no panel behind it.
  • "Dark panel + gold trim" — a dark card with gold border.
  • "Header / border tweaks" — a small delta that keeps the rest of the template.
  • "Match the stage" — echo a stage's frame (border color/width/radius) onto the modal.
  • A "FULL WINDOW THEME" map that re-skins the ENTIRE offering flow at once (the offer modal, the Add Items item picker, the confirm popup, AND the reward window) — panel background, title bar, body text, accent/highlight, field colors, the full button set, and each window's border/radius. There is also a companion set using the same keys with a "comp_" prefix.

You can merge the window theme, the companion set, and any card-styling keys into ONE map for a row.

ODDS, LUCK & OFFERINGS (THE MATH)

This is exactly how drop rates, luck, and offerings work. (It used to live on a separate "More Information" tab — it's here now so the whole guide is in one place.)

RARITY TIERS VS. DROP RATES

Two separate things control your loot — don't confuse them:

1) DROP RATE — how often an item appears. This comes ONLY from the 'weight' you give each outcome in a loot table (Loot tab). Weights are relative: an outcome's chance is its weight divided by the total of all weights. To make a legendary appear ~0.5% of the time and a common ~70%, you give them weights like 0.5 and 70. The game does NOT infer this from the rarity name.

2) RARITY TIER — an item's rank in your Currency System rarity ladder (set by the item's rarity, e.g. plentiful, common, ... legendary). This is used ONLY to scale luck: each item's weight is multiplied by (1 + L x tier). It is a label/rank, not a rate.

So the rarity tag does NOT make an item rare — the weight does. Keep them consistent: give rare items BOTH a low weight AND a high rarity tag. A 'legendary' tagged item with a large weight will still drop constantly (and luck will over-boost it).

weight (Loot tab) -> base odds (how often it drops)
rarity tier (Currency System) -> how much luck boosts it

OFFERINGS

If 'Minimum offering' is above 0, a gacha instance's button opens a modal where a player offers currency and/or items to play. Items are valued at their sell price; the offering must be worth at least the minimum or it is rejected.

Offering MORE than the minimum grants a temporary luck bonus (L) for that roll — better odds of rarer rewards. Two settings shape it: 'Max luck bonus from over-offering' (the most luck a huge offering can reach) and 'Offering for half the max bonus' (how much OVER the minimum earns half of that max).

How the bonus scales with the offering:
L = max x over / (over + half) (over = offering value - minimum)

It rises fast at first, then flattens — approaching the max but never reaching it (no guaranteed jackpot). When 'over' equals the half-point, L is exactly half of the max.

Example — minimum 50, max 1.0, half-point 100:
offer 50 (over 0) -> L 0.00
offer 100 (over 50) -> L 0.33
offer 150 (over 100) -> L 0.50 (over = half-point)
offer 250 (over 200) -> L 0.67
offer 550 (over 500) -> L 0.83
offer huge -> L ~1.00

Smaller half-point = odds ramp up quickly; larger = a player must offer much more to feel it.

LUCK & ODDS (OVER-OFFERING AND BUFFS)

Luck (L) biases a loot roll toward rarer items. It comes from over-offering a gacha instance (above) and from Luck buffs — both use the same math. Each item outcome's weight is multiplied by:
(1 + L x tier)

'tier' is the item's rank in your Currency System rarity ladder, lowest = 0 (e.g. plentiful, common, uncommon, rare, very rare, legendary -> 0,1,2,3,4,5). Currency / nothing / buff outcomes sit at tier 0 (unchanged), so luck shifts the roll away from those and toward rarer item drops.

The boost is LINEAR in the tier, so rarer items climb proportionally — they get luckier but stay rare. Weight multipliers:
L 0.5: common x1.5 uncommon x2 rare x2.5 very rare x3 legendary x3.5
L 1.0: common x2 uncommon x3 rare x4 very rare x5 legendary x6

Weights are relative, so a rare item at a low weight stays uncommon even when boosted — its odds just improve. Keep L modest (about 0.5 to 1); the same L applies to Luck buff levels.

THE SETUP INSTRUCTIONS TAB

The plugin's built-in Setup Instructions tab is a quick-start checklist — the load-order rule (Currency System above the Minigame Suite) and the scene placeholder for putting a game on a page. This guide expands on it and never contradicts it.

A SANE ORDER TO BUILD IN

  1. Confirm load order (Currency System above MS).
  2. Decide your global rules on General Settings (caps, who can earn, styling match).
  3. Define any Buffs you want (Buffs tab).
  4. Build a Stage (Game Staging).
  5. Build a Gacha Instance on it (Gacha Games).
  6. Give the instance a Loot Table (Loot Tables) — mind the weights.
  7. (Optional) Turn on Post Drops and fill its post_drops loot.
  8. (Optional) Tweak the look on Game Modal Templates / Styling Overrides.
  9. Paste the placeholder to place the scene, and test as a normal member (turn Staff test mode off first).
