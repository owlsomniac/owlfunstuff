Overview

Currency System Extras is a key-free companion that re-skins the Currency System’s interface and adds a handful of optional features. It stores nothing of its own and needs no keys or permissions — it just has to load below the Currency System.

Its main job is a full color theme: a complete palette, with opacity, for every surface — shop, inventory, HUD, modals, popups, notices, toasts, and item cards — layered so you only fill in what you want to change. On top of that it adds card-flip item descriptions, item cards you can drop into posts, a member history panel, an admin transaction-log viewer, and bulk-sell conveniences.

Load order: Currency System → Currency System Extras → Minigame Suite.

Instruction Manual

The Setup Instructions inside the plugin’s own settings are a quick-start checklist. This is the full, plain-English walkthrough of every feature.

This manual explains every feature of Currency System Extras (CS Extras) and exactly how to use it. It is written for a forum admin who has never touched the plugin and is not technical — it assumes you know nothing and walks you through each control step by step.

Everything described here is set on the TABS of THIS plugin. When you edit a ProBoards plugin you get a row of tabs across the top of its settings window; CS Extras has these tabs (also called "pages"):

  • Setup Instructions
  • Settings
  • General Theme
  • Panels
  • Modals
  • Notice Popup
  • Toasts
  • Currency Pill + HUD
  • Item Cards

This manual is the deep, feature-by-feature walkthrough. It complements — it does not replace — the short quick-start on the plugin's own "Setup Instructions" tab. If you just want the 3-line install checklist, read that tab; if you want to understand and use every feature, read this.

How to read this manual: each feature section tells you (1) in plain English what the feature is, (2) which TAB it lives on, (3) numbered how-to steps, (4) a concrete worked example, and (5) tips and things that commonly trip people up.

WHAT CS EXTRAS IS AND HOW IT RELATES TO THE CURRENCY SYSTEM

Currency System Extras is an ADD-ON to another plugin called the Currency System. The Currency System is the real engine: it runs your forum economy — the wallet, the shop, buying and selling, the inventory, the admin page. CS Extras does not create any of that and cannot run on its own. It sits on top of the Currency System and does two jobs, and only these two jobs:

  1. It applies a color THEME to the Currency System's existing screens (shop, inventory, pop-ups, the wallet badge, and so on) so they match your forum instead of using plain default styling.
  1. It adds a handful of EXTRA pieces of interface that the base plugin does not include on its own: a card "flip" that reveals an item's description, item cards you can drop into forum posts, a personal transaction-history panel for members, and a staff-only transaction-log viewer.

That is the whole plugin. If you remove CS Extras, your economy keeps working exactly as before — it just goes back to looking plain and loses those four extra pieces of UI.

KEY-FREE: nothing to set up, nothing stored

Many ProBoards plugins need "keys" — hidden storage slots — plus permission settings before they work. CS Extras is KEY-FREE. It stores NOTHING. There are no keys to create, no permissions to grant, no per-member data to manage. Every reading it needs (balances, item names, transaction history) it borrows live from the Currency System at the moment a page loads. This is why the plugin is safe to add and remove freely: it is purely a coat of paint plus some extra display, and it never holds any of your data.

LOAD ORDER: CS Extras must sit BELOW the Currency System

On your forum's Plugins page (Admin area), installed plugins are listed top to bottom, and they load in that order — top first, bottom last. CS Extras has to load AFTER the Currency System so that, by the time CS Extras runs, the economy screens already exist for it to paint and extend.

The correct order, top to bottom, is:

  1. Currency System (the base engine — must be ABOVE Extras)
  2. Currency System Extras (this plugin)
  3. Minigame Suite (only if you use it)

To reorder, drag the plugins on the Plugins page so they line up like that.

If a tool or panel does not appear

Almost every "it is not showing up" problem is one of two things:

  • The Currency System is not actually installed, or
  • The Currency System is installed but loads BELOW CS Extras (wrong order).

Extra UI that CS Extras adds — the flip button, in-post item cards, the member history panel, the admin log viewer — can only appear when the base Currency System is present and loads first. If something is missing, fix the load order (Currency System ABOVE Extras) before troubleshooting anything else.

THE THEMING MODEL — THE ONE IDEA THAT MAKES EVERYTHING EASY

Before touching any color, learn this mental model. Once it clicks, every theming tab in the plugin makes sense. CS Extras builds its look in THREE STACKED LAYERS. Each layer can override the one beneath it, and anything you leave blank simply falls through to the layer below.

Layer 1 — the base PRESET

On the "General Theme" tab there is a setting called "Theme" with three choices: CS Theme, Light, and Dark. This is the foundation — the ready-made palette everything starts from. You pick ONE. Think of it as the undercoat of paint.

Layer 2 — the General Theme color "buckets"

Also on the "General Theme" tab, below the preset, is a long list of broad color controls grouped into buckets (Surfaces, Fields, Text, Accents, Buttons, Borders & Effects). Anything you set here overrides the preset EVERYWHERE AT ONCE. For example, setting "Accent" here recolors every price, total and wallet figure across the whole plugin in one move. This is your broad brush.

Layer 3 — the per-surface tabs

The tabs named Panels, Modals, Notice Popup, Toasts, Currency Pill + HUD, and Item Cards each control ONE surface (one kind of screen). A value you set on one of these tabs overrides the General Theme for THAT surface only, and changes nothing else. This is your fine detail brush — for when one screen needs to differ from the rest.

THE GOLDEN RULE: blank = inherit the layer above

This is the single most important sentence in the whole manual:

EVERY color box or field you leave BLANK inherits the value from the layer above it.

So you only ever fill in the few things you actually want to CHANGE. You never have to fill in a whole screen. A blank field on the Panels tab looks to the General Theme; a blank bucket on the General Theme looks to the preset. Leave a whole surface tab empty and that surface just wears the General Theme. This is why installing CS Extras with all defaults is safe and calm: almost everything is blank, so almost everything simply inherits.

Practical consequence: to restyle something, do NOT try to fill in every box. Change the one or two boxes that are wrong and leave the rest blank.

How to type colors and opacity

Two formatting rules apply everywhere in the plugin:

  • COLOR fields take a hex code WITHOUT the leading "#". For example, to use the color #1E90FF you type "1E90FF". (Many color fields also show a little swatch/picker you can click instead of typing.)
  • OPACITY fields take a number from 0 to 100, where 100 means fully solid and 0 means fully invisible. Some opacity-style fields also accept a percent sign (for example "80" or "80%") — the on-screen help for each field tells you which. Lower numbers = more see-through.

A few size/spacing fields take pixel values like "8", "8px", or even two numbers like "60px 50px" for padding. Each field's help text gives an example.

The safe way to experiment

Because blank = inherit and nothing is stored, theming is completely reversible. To undo any change, empty the box again — it returns to inheriting. To reset a whole surface, blank out every box on its tab. There is no way to damage your data by trying colors, so experiment freely, save, and look at the result on your forum.

THE "GENERAL THEME" TAB IN DETAIL

TAB: General Theme.

This is Layer 1 (the preset) and Layer 2 (the broad buckets) from the model above, both living on one tab. It is the baseline every surface starts from. Set things here and they apply to panels, modals, pop-ups, the wallet pill, item cards, the log viewer — everything the plugin touches — unless a per-surface tab overrides them.

Work top to bottom: pick the preset first, then adjust only the buckets you care about.

Step 1 — pick the base preset ("Theme")

The very first control is "Theme". Choose one:

  • CS Theme — THIS IS THE DEFAULT. It is the plugin's own "frosted" look (semi-transparent, softly blurred panels) that is designed to read well on ANY forum background. Because it matches the base Currency System's own frosted styling, installing CS Extras with defaults changes NOTHING visually — the screens look the same as they did with just the Currency System. (Note: the plugin's older on-screen help may say the default is "Light" — that is out of date. The real default is CS Theme.)
  • Light — a clean, solid, light palette (opaque light panels). Choose this if your forum is light and you want plain solid boxes rather than the frosted look.
  • Dark — a solid dark palette. Choose this for dark forums.

How to set it: click the radio button next to the preset you want. Everything else on this tab is optional and only overrides the preset where you fill it in.

Group: SURFACES — the boxes themselves

"Surfaces" means the solid shapes everything sits on — the panels, cards, pop-ups and their recessed areas. Controls:

  • "Panel Background" — the fill color shared by panels, modals, cards, popups and dropdowns (they are all one color). Blank = the preset's color.
  • "Panel Opacity" — how see-through panels are. Accepts a number with or without % (e.g. 80 or 80%). Blank = solid.
  • "Surface Opacity" — opacity for modals, popups and notices specifically. Because these float OVER your content, they default a little more solid than flat panels so text stays readable. Blank = default (100%).
  • "Insets" — the color of recessed areas: icon-card thumbnails and sunken "wells". Blank = the preset's color.
  • "Inset Opacity" — a 0–100 opacity for those wells/insets on their own. Blank = they frost along with Panel Opacity.

Worked example: to make every panel a touch translucent so your forum background shows through, set "Panel Opacity" to 85 and leave the colors blank.

Group: FIELDS — text input boxes

These two control the little boxes members type into (search boxes, quantity boxes, etc.):

  • "Text Field Background" — the fill behind an input box. Blank = the preset's color.
  • "Text Field Text" — the color of the text a member types into that box. Blank = the preset's color.

Tip: keep these two in strong contrast (dark text on light field, or vice versa) so typed input stays legible.

Group: TEXT — every kind of writing

This is the largest group. It controls the colors, emphasis (bold/italic/underline) and fade (opacity) of each category of text, PLUS the panel titles. Going through it:

Headings and their style:

  • "Modal / Dialog / Log Headers" — the titles inside pop-up dialog boxes (Buy, Sell, confirm boxes) and the column headers of the admin log table. Blank = preset.
  • "Popup Headers" — the heading inside the floating notice popup (the "you were granted…" message). Blank = preset.
  • "Heading Style" — tick any of Bold / Italic / Underline to apply to ALL headings at once. Per-surface tabs can override this. Blank = no styling.
  • "Heading Opacity" — 0–100, fades all heading text. Blank = 100.

Body text and its style:

  • "Body Text" — the main copy (ordinary sentences) everywhere. Blank = preset.
  • "Body Style" — Bold / Italic / Underline for all body copy. Blank = none.
  • "Body Opacity" — 0–100, fades all body text. Blank = 100.

Note / muted text and its style:

  • "Note / Muted Text" — the quieter secondary copy (hints, sub-labels). Blank = preset.
  • "Note Style" — Bold / Italic / Underline for all muted copy. Blank = none.
  • "Note Opacity" — 0–100, fades all muted text. Blank = 100.

Category section headers (shop/inventory):

  • "Category Headers" — the color of the section-title text that groups items in the shop and inventory (independent of the "Heading" color above). Blank = preset.
  • "Category Header Background" — the fill of those category bands. Blank = the CS Theme / Dark preset default (independent of Insets).

Panel titles (the big title at the top of each economy screen — shop, inventory, admin — these titles are created by the Currency System; CS Extras just styles them):

  • "Panel Header Text" — the color of those panel titles. Blank = follows the Body Text color.
  • "Panel Header Background" — a band behind the panel title. Set a color and the title becomes a padded, rounded colored band; blank = no band (off). This also affects modal/popup titles unless a surface tab overrides them.
  • "Panel Header Text Size" — font size of all panel titles, e.g. 15px. Blank = default size.
  • "Panel Header Text Style" — Bold / Italic / Underline for all panel titles. Blank = none.
  • "Panel Header Alignment" — Left, Center or Right for all panel titles. Blank = default (left).

Worked example: to give every screen a bold, centered title sitting on a colored bar, set "Panel Header Background" to your brand color (e.g. 2A3F5F), tick Bold under "Panel Header Text Style", and choose Center under "Panel Header Alignment".

Group: ACCENTS — the three "meaning" colors

Accents are the colors that carry meaning rather than fill space. There are three:

  • "Accent" — used for VALUES: prices, amounts and totals, the wallet balance, the currency symbol, the "?" glyph, the category-header bar, badge backgrounds, and "Show more". This is the single most impactful color for making the economy feel "yours" — it is every number a member looks at. Blank = preset.
  • "Highlight" — used for INTERACTIVE feedback: the focus ring, status messages, hover states, dropdown options, a selected checkbox, card outlines and dropdown-panel borders. Blank = preset.
  • "Danger / Error" — used for validation errors and remove/delete actions. Blank = preset.

Worked example: to make all prices and the wallet balance gold, set "Accent" to C9A227 and leave Highlight and Danger blank.

Group: BUTTONS — every clickable button

These style the buttons across all economy screens in one place:

  • "Button Background" — the fill. Blank = preset.
  • "Button Text" — the label color. Blank = preset.
  • "Button Hover Background" — the fill while the mouse is over it. Blank = preset.
  • "Button Hover Text" — the label color on hover. Blank = preset.
  • "Button Border" — the outline color. Blank = follows the general Border Color.
  • "Button Border Width" — thickness, e.g. 1 or 1px. Blank = 1px.
  • "Button Border Opacity" — 0–100 for the border color. Blank = 100.
  • "Button Corner Radius (px)" — roundness of corners. Blank = default (6). 0 = square corners.
  • "Button Vertical Padding (px)" — the button's height/thickness. Blank = default (9). Lower = slimmer.
  • "Button Horizontal Padding (px)" — the side padding / width. Blank = default (16).

Worked example: for slim, square, high-contrast buttons set Button Corner Radius to 0, Button Vertical Padding to 6, Button Background to 1E90FF and Button Text to FFFFFF.

Group: BORDERS & EFFECTS — outlines everywhere

The overall outline treatment for the whole plugin:

  • "Show Borders" — Show or Hide ALL borders at once. Default: Show. Choose Hide for a clean, borderless look.
  • "Border Color" — the color of every border (independent of the Accent). Blank = preset.
  • "Border Width" — thickness of borders, a number with or without px, e.g. 1 or 1px. Blank = 1px.

Tip: "Show Borders = Hide" wins over any Border Color you set — if you hid borders and then wonder why a color has no effect, that is why.

THE "PANELS" TAB

TAB: Panels.

What it is: per-surface overrides for the big economy PANELS — the Shop, Inventory, Sell, Buy, Admin and search panels. This is Layer 3 for those screens. Every field here defaults to BLANK = inherit the General Theme, so fill in only what you want different from the rest of your forum.

IMPORTANT — two screens with no tab of their own are styled here too: the member Transaction-History panel and the admin Transaction-Log viewer. Neither has its own tab; both are treated as Panels. So if you want the history panel or the log viewer to look a particular way, you set it on THIS tab, and it inherits from the General Theme just like the shop and inventory do.

The field groups on this tab

The controls are grouped the same way you will see them repeated on the Modals and Notice Popup tabs, so learning them once covers all three:

TEXT group:

  • "Heading" — heading/title text color on panels. Blank = inherit General.
  • "Heading Style" — Bold / Italic / Underline the headings. Blank = inherit General.
  • "Header Background" — a band behind this surface's title. Blank = off / inherit the General header band.
  • "Header Bg Opacity" — 0–100 for that band. Blank = 100.
  • "Body Text" — main copy on panels. Blank = inherit General.
  • "Body Style" — Bold / Italic / Underline body copy. Blank = inherit General.
  • "Note / Muted Text" — secondary copy on panels. Blank = inherit General.
  • "Accent / Values" — the price/total/value color on panels. Blank = inherit General (Accent).
  • "Note Style" — Bold / Italic / Underline muted copy. Blank = inherit General.
  • "Text Opacity" — 0–100, fades body + note text. Blank = inherit General.

BACKGROUNDS group:

  • "Background" — the panel fill color. Blank = inherit General.
  • "Background Opacity" — 0–100. Blank = inherit General.

BORDERS group:

  • "Border Color" — Blank = inherit General.
  • "Border Width" — e.g. 1 or 1px. Blank = inherit General.
  • "Corner Radius (px)" — roundness, e.g. 8; 0 = square. Blank = inherit General.

BUTTONS group (overrides just the buttons on panels):

  • "Button Background", "Button Text", "Button Hover Background", "Button Hover Text", "Button Border" — all Blank = inherit General.
  • "Button Border Width" — e.g. 1 or 1px. Blank = inherit General.
  • "Button Border Opacity" — 0–100. Blank = inherit General.
  • "Button Corner Radius (px)" — Blank = inherit General.

CATEGORY HEADERS group (only panels have these — the collapsible category bands in the shop and inventory):

  • "Background" — the category band fill. Blank = the Inset color.
  • "Background Opacity" — 0–100. Blank = 100.
  • "Text" — the category name + the little caret. Blank = the General "Category Headers" color.
  • "Border Color" — the band border. Blank = the General Border color.
  • "Border Width" — e.g. 1 or 1px. Blank = none.

Worked example

Say your General Theme is dark, but you want the shop and inventory panels a shade lighter with brighter category bands. On the Panels tab set "Background" to 24304A and, under CATEGORY HEADERS, set "Background" to 33436A and "Text" to FFFFFF. Leave everything else blank. Only the panels change; modals, pop-ups and the pill still wear the darker General Theme.

Reminder: because the member history panel and admin log viewer are styled as Panels, that same lighter background now also applies to them — which is usually what you want, since they are panels too.

THE "MODALS" TAB

TAB: Modals.

What it is: per-surface overrides for the POP-UP DIALOG boxes that open on top of the page — the item-detail modal, the Buy and Sell dialogs, and the confirm/error dialogs. Blank = inherit the General Theme.

The field groups are identical to the Panels tab — TEXT (Heading, Heading Style, Header Background, Header Bg Opacity, Body Text, Body Style, Note / Muted Text, Accent / Values, Note Style, Text Opacity), BACKGROUNDS (Background, Background Opacity), BORDERS (Border Color, Border Width, Corner Radius), and BUTTONS (Background, Text, Hover Background, Hover Text, Border, Border Width, Border Opacity, Corner Radius). Everything defaults to BLANK = inherit General. (Modals have no Category Headers group — only panels do.)

Worked example

To make dialog boxes stand out from the page behind them, give modals a solid, slightly darker background and a bright accent. On the Modals tab set "Background" to 1B2233, "Background Opacity" to 100, and "Accent / Values" to 4FC3F7. Now Buy/Sell/confirm dialogs read as crisp solid cards even if your panels are frosted.

THE "NOTICE POPUP" TAB

TAB: Notice Popup.

What it is: overrides for the floating NOTICE popup — the box that appears to tell a member something happened, for example "An Admin granted you…". (This is a different thing from the small auto-dismissing toast; the toast has its own tab, covered next.) Blank = inherit the General Theme.

The one thing that confuses everyone: TWO title bands

The notice popup has TWO separately colored horizontal bands stacked at its top, and they are easy to mix up. Read this slowly:

  1. THE NOTICE TITLE BAND — the very top strip that just says "Notice". It is controlled by:

• "Notice Heading Text" — the color of the word "Notice". Blank = the modal heading color (matches a plain title).
• "Notice Header Background" — the band behind the word "Notice". Blank = off / inherit the General header band.
• "Notice Header Bg Opacity" — 0–100 for that band. Blank = 100.

  1. THE MESSAGE BAND — the strip just below it carrying the actual message, e.g. "An Admin granted you…". It is controlled by:

• "Message Heading Text" — the color of that granted-you line. Blank = the modal heading.
• "Message Header Background" — the band behind the message line. Blank = off / inherit the General header band.
• "Message Header Bg Opacity" — 0–100 for that band. Blank = 100.

So "Notice…" fields = the top "Notice" strip; "Message…" fields = the message strip beneath it. They are independent on purpose, so you can style them differently.

The rest of the tab

Below the two bands are the usual groups, all Blank = inherit General:

TEXT: "Heading Style" (Bold/Italic/Underline applies to BOTH headings), "Body Text", "Body Style", "Note / Muted Text", "Accent / Values", "Note Style", "Text Opacity".
BACKGROUNDS: "Background", "Background Opacity".
BORDERS: "Border Color", "Border Width", "Corner Radius (px)".
BUTTONS: "Button Background", "Button Text", "Button Hover Background", "Button Hover Text", "Button Border", "Button Border Width", "Button Border Opacity", "Button Corner Radius (px)".

Worked example — coloring the two bands differently

Goal: a green "Notice" strip on top and a neutral dark message strip below. Set "Notice Header Background" to 2E7D32 and "Notice Heading Text" to FFFFFF; then set "Message Header Background" to 263238 and "Message Heading Text" to E0E0E0. Now the popup reads as a green banner labelled "Notice" over a dark bar carrying "An Admin granted you…". Leave the other fields blank so the body and buttons stay on-theme.

THE "TOASTS" TAB

TAB: Toasts.

What it is: the small pop that slides in briefly and then disappears by itself when a member earns or spends — for example "+0.1 Coins" after earning, or "Purchased Trait Potion" after buying. It is separate from the notice popup and has its own small set of controls. Blank = inherit the General Theme.

The controls

TEXT group:

  • "Text" — the toast message color. Blank = the Accent color (so by default the toast matches your currency figures).
  • "Text Opacity" — 0–100 for that text color. Blank = 100.
  • "Text Style" — Bold / Italic / Underline the toast text. Blank = the theme default.

SURFACE group:

  • "Background" — the toast fill. Blank = the General Background.
  • "Background Opacity" — 0–100. Blank = the General Panel Opacity.

BORDERS group:

  • "Border Color" — Blank = the General Border.
  • "Border Opacity" — 0–100 for the border color. Blank = 100.
  • "Border Width" — e.g. 1 or 1px. Blank = the General Border Width.
  • "Corner Radius (px)" — roundness, e.g. 8. Blank = 8px.

Remember the special default: leave "Text" blank and toast text automatically uses the Accent color, keeping earn/spend pops visually tied to your money color.

Worked example

For a subtle, rounded, semi-transparent toast that still shows earnings in your accent color: leave "Text" blank (so it stays Accent), set "Background" to 111111, "Background Opacity" to 80, and "Corner Radius (px)" to 14. Earn/purchase pops now appear as soft dark pills with accent-colored text.

THE "CURRENCY PILL + HUD" TAB

TAB: Currency Pill + HUD.

This single tab has FOUR labeled sections, top to bottom: CURRENCY PILL, HUD BACKDROP, and BUFF HUD (which itself contains a TEXT area and a "?" BUTTON area). Together they style the little wallet badge and the strip of interface around it. Blank pickers fall back to the accent/theme colors.

Section 1 — CURRENCY PILL (the wallet badge in the nav bar)

The "pill" is the small rounded badge showing a member's balance, usually up in the navigation bar. Controls:

  • "Padding" — inner spacing of the pill, e.g. 4px 12px. Blank = default padding.
  • "Corner Radius" — how rounded the pill is, e.g. 12px. Blank = default.
  • "Background Color" — the pill's fill. Blank = frosted panel color.
  • "Background Opacity" — 0–100 for that fill. Blank = 100.
  • "Currency Text Color" — the color of the BALANCE FIGURES in the pill only. (Note: the buff strip beside the pill does NOT use this — its "Active Buffs:" label follows the General Body text and its buff names/timers follow the General Muted text.) Blank = accent.
  • "Text Opacity" — 0–100 for the balance text. Blank = 100.
  • "Font Size" — balance text size, e.g. 13px. Blank = default.
  • "Border Color" — the pill's border. Blank = accent.
  • "Border Width" — border thickness, e.g. 1px. Blank = default.
  • "Border Opacity" — 0–100 for the border color. Blank = 100.

Worked example: to make the wallet badge a solid brand-colored chip with white numbers, set "Background Color" to 1E88E5, "Background Opacity" to 100, and "Currency Text Color" to FFFFFF.

Section 2 — HUD BACKDROP (the square panel behind the pill)

Behind the rounded pill (and the buff strip, if you run the Minigame Suite) there is a square backing panel. This section controls that rectangle — NOT the pill itself.

  • "Show HUD Backdrop" — Show (default) or "Hidden (transparent)". Choose Hidden to make that square panel fully transparent for a clean, backdrop-free HUD where only the rounded pill shows.
  • "HUD Backdrop" — the color to paint that square panel. Blank = transparent.

CRITICAL GOTCHA: "Hidden" OVERRIDES any color. If you set "Show HUD Backdrop" to Hidden, the backdrop is transparent even if you also typed a "HUD Backdrop" color. To actually see the color, "Show HUD Backdrop" must be Show.

Worked example: for a floating pill with no box around it, set "Show HUD Backdrop" to Hidden and ignore the color field. To instead paint the backing a dark slab, set "Show HUD Backdrop" to Show and "HUD Backdrop" to 141414.

Section 3 — BUFF HUD (the Minigame Suite "Active Buffs:" strip)

If you also run the Minigame Suite, it adds a strip beside the pill that lists active buffs (the "Active Buffs:" bar). This section overrides that strip's colors. All text here is Blank = inherit the General Theme (the label inherits Body, names/timers inherit Muted).

TEXT area:

  • "Label Text" — the "Active Buffs:" label and the strip's inline text. Blank = the General Body text.
  • "Buff Names / Timers" — the buff names, countdown timers, and the guide rows (both on the strip and inside the "?" card). Blank = the General Muted text.

"?" BUTTON area (the little help button on the strip):

  • "Button Background" — the fill of the strip's "?" button. Blank = follows the button colors (same as the shop/inventory "?").
  • "Button Icon" — the color of the "?" glyph. Blank = follows the button text color.
  • "Button Border" — the border of the "?" button. Blank = follows the button border.

GOOD TO KNOW — the "?" guide CARD needs no controls of its own. When a member clicks the "?", the little guide card that pops open AUTOMATICALLY wears the Currency Pill's background, opacity and border, and uses the "Label Text" color for its title. So you style that card indirectly, through the Currency Pill section and Label Text — there are no separate boxes for it.

Worked example: to make the buff strip label bright and its "?" button match your accent, set "Label Text" to FFFFFF and "Button Background" to 1E88E5; leave the guide card alone — it follows the pill automatically.

THE "ITEM CARDS" TAB

TAB: Item Cards.

What it is: styling for the little item "cards" — the tiles showing an item's picture and name — everywhere they appear. This tab is organized around ONE key distinction, so learn it first before touching anything.

THE KEY DISTINCTION — colors are global, layout is per-surface

Item cards show up in several different places, but you do NOT recolor them place by place. Instead:

  • COLORS & STYLE are GLOBAL — one set of colors applies to EVERY item card, everywhere, at once. There is exactly ONE exception: the "Item Picker (Add Items, Bulk Sell)" has its OWN separate colors (its section at the bottom).
  • PHYSICAL properties — fill opacity, border opacity, whether rarity borders show, image size, and card size/padding — are set PER SURFACE, because different screens want different sizes. There are SIX card surfaces, each with its own little block of physical controls:

1. Shop Grid
2. Inventory Grid
3. In-Post Cards
4. Buy Modal
5. Sell Modal
6. Reward Popup (Minigame Suite)

So: pick your card COLORS once at the top; then tune SIZE/opacity for each of the six surfaces as needed; the Item Picker gets its own colors at the end.

Group: COLORS & STYLE (applies to all item cards)

This top group sets the one global color scheme for every card:

  • "Background" — the card's front fill. Blank = the General Theme Inset color.
  • "Flip Background" — the fill of the FLIPPED card back (the description side); its own color, separate from the front. Blank = the Field Background.
  • "Text" — the item-name text. Blank = the General Body Text color.
  • "Flip Text" — the description text on the flipped back. Blank = the card Text color.
  • "Text Style" — Bold / Italic / Underline the item-name text on all cards. Blank = none.
  • "Accent (Price)" — the price line on shop cards. Blank = the General Accent color.
  • "Border" — the card outline / hover highlight. Blank = the General Highlight color.
  • "Border Width" — e.g. 1 or 1px. Blank = the General Border Width.
  • "Corner Radius (px)" — e.g. 8; 0 = square. Blank = default.

The flip "?" button on cards that have a description (its colors, including the HOVER colors):

  • ""?" Button Background" — its fill. Blank = the Button Background.
  • ""?" Button Icon" — the "?" glyph color. Blank = the Accent color.
  • ""?" Button Border" — its border. Blank = the Button Border color.
  • ""?" Button Hover Background" — fill while hovered. Blank = the Button Hover Background (then falls back to the "?" Button Background).
  • ""?" Button Hover Icon" — glyph color while hovered. Blank = the Button Hover Text (then the "?" Button Icon).
  • ""?" Button Hover Border" — border while hovered. Blank = the Button Hover Border (then the "?" Button Border).

The inventory owned-count badge (the little "×N" that shows how many you own):

  • "Counter Background" — its fill. Blank = the Button Background (matches the "?" chip).
  • "Counter Text" — the number color. Blank = the Button Text color.

The six PER-SURFACE layout blocks

Each of the six surfaces below has the SAME four or five physical controls. Set them only where a given surface needs a different size or transparency; blank = the stated default.

Each block has:

  • "Fill Opacity" — 0–100, background transparency of that surface's cards. Blank = 100.
  • "Border Opacity" — 0–100, border transparency. Blank = 100.
  • "Rarity Borders" — Show (default) or Hide the rarity-tier border on that surface. (See the rarity note below.)
  • "Image Size" — the item picture size, e.g. 48px. Blank = default.
  • "Card Size (padding)" — padding around the item, i.e. how big the card is around its icon, e.g. 12px or 60px 50px. Blank = default.

The six blocks are:

  1. SHOP GRID — cards in the shop listing.
  2. INVENTORY GRID — tiles in a member's inventory.
  3. IN-POST CARDS — the cards produced by the [item=Name] tag in posts (see the Item Cards in Posts feature).
  4. BUY MODAL — the item image inside the Buy dialog.
  5. SELL MODAL — the item image inside the Sell dialog.
  6. REWARD POPUP (MS) — the card in the Minigame Suite's reward popup (only applies if the Minigame Suite is installed).

ONE naming difference to note: on the Reward Popup surface the rarity control is called "Rarity Glow" (not "Rarity Borders"), because the Minigame Suite draws a glow from each item's rarity using its own built-in fallback palette. That means the reward glow works even when the Currency System's rarity borders are turned off; set "Rarity Glow" to Hide to suppress it on just that one surface.

About rarity borders in general

The per-surface "Rarity Borders" toggles only DISPLAY rarity coloring — they cannot invent it. For rarity borders to actually appear, rarity must be turned on and given tier colors in the CURRENCY SYSTEM plugin (its "Styling + CSS" and "Shops" tabs). If you have not set that up in the base plugin, switching "Rarity Borders" to Show here does nothing. The single exception is the Reward Popup's "Rarity Glow", which the Minigame Suite can draw on its own.

Group: ITEM PICKER (Add Items, Bulk Sell) — its own colors

This is the ONE place with its own color set, separate from the global card colors above. The Item Picker is the searchable list of items staff use in the Add Items and Bulk Sell tools. Its controls:

  • "Background" — the row/thumbnail fill. Blank = the General Inset color.
  • "Fill Opacity" — 0–100 for that fill. Blank = 100.
  • "Text" — the item-name text in the picker. Blank = the General Body Text color.
  • "Accent" — the value text in the picker (the "owned N · price ea" detail line and the row line totals). Blank = the General Accent color.
  • "Text Style" — Bold / Italic / Underline the picker item names. Blank = none.
  • "Border" — the row outline. Blank = the General Border color.
  • "Border Width" — e.g. 1 or 1px. Blank = the General Border Width.
  • "Border Opacity" — 0–100. Blank = 100.
  • "Corner Radius (px)" — e.g. 6. Blank = default.
  • "Rarity Borders" — Show (default) or Hide rarity-tier borders on the picker rows (same Currency-System requirement as above).
  • "Image Size" — thumbnail picture size, e.g. 48px. Blank = default.
  • "Card Size (padding)" — padding around the item on picker rows, e.g. 12px or 60px 50px. Blank = default.

Worked example

Goal: soft rounded item cards whose price stands out, with slightly transparent shop tiles. In COLORS & STYLE set "Corner Radius (px)" to 10 and "Accent (Price)" to C9A227 (gold). Then under SHOP GRID set "Fill Opacity" to 90. Leave the inventory, modal, post and reward blocks blank so they keep the defaults. The gold price and rounded corners apply to every card at once; only the shop tiles turn slightly translucent.

CARD FLIP — REVEAL AN ITEM DESCRIPTION

TAB: Settings (control: "Flip Card for Description").

What it is: a small "?" button placed on shop and/or inventory item cards. When a member clicks it, the card FLIPS OVER to show that item's description on the back, then flips again to go back. It is a tidy way to show item descriptions without cluttering the front of the card. (The look of the flipped side is styled by the "Flip Background" and "Flip Text" colors on the Item Cards tab.)

How to turn it on

  1. Open the Settings tab.
  2. Find "Flip Card for Description" (under the CARD FLIP heading).
  3. It is a set of tickboxes. Tick "Shop" to add the flip "?" to shop cards, and/or tick "Inventory" to add it to inventory cards. You can tick one, both, or neither.
  4. Save.

Defaults: both boxes are unticked (blank), so nothing flips until you turn it on. This feature needs the Currency System present (it supplies the item descriptions).

Worked example: tick only "Shop" so shoppers can flip a shop card to read what an item does before buying, while inventory tiles stay simple.

ITEM CARDS IN POSTS — EMBED A SHOP ITEM IN A POST

TAB: Settings (controls: "Item Cards in Posts" and "Default Icon Size (px)").

What it is: when this is on, members can drop a live item card straight into a forum post by typing a short tag. They type [item=Name] and, where they typed it, a small card appears showing that item's icon and name — and it flips to the description on its "?" button, just like a shop card. This is great for trade threads, guides, and roleplay where people want to reference specific items. It is OFF by default so the [item=…] tag is only parsed if you want it.

How to turn it on and set the default size

  1. Open the Settings tab.
  2. Find "Item Cards in Posts" (under the ITEM CARDS IN POSTS heading) and set it to "On". (It is a two-choice On/Off control; "Off" is the default.)
  3. Optionally set "Default Icon Size (px)" — the icon size used when a member does not specify one. Default is 48.
  4. Save.

Requires the Currency System to be present, since the card is built from a real shop/registered item.

How members use it, and the size option

In a post, a member types:

  • [item=Trait Potion] — inserts a card for the item named "Trait Potion". Any shop or registered item can be referenced (you can also reference an item by its id).
  • [item=Trait Potion size=64] — same card but with a 64px icon. Adding "size=NN" overrides the Default Icon Size for that one card.

Worked example: with the feature On and "Default Icon Size (px)" left at 48, a member writes "Selling my spare [item=Trait Potion size=64] — make an offer." The post shows a 64px Trait Potion card that flips to reveal the potion's description.

The physical look of these in-post cards (fill/border opacity, rarity border, image and card size) is tuned on the Item Cards tab under the IN-POST CARDS block; their colors come from the global card colors.

MEMBER TRANSACTION-HISTORY PANEL

TAB: Settings (controls: "Show Profile History Panel", "History Panel", "Profile History Entry Count", "History Scroll Height (px)", plus the MEMBER LOG TYPES toggles).

What it is: a panel that shows a member their OWN transaction history — a running list of what they earned, bought, sold, and what admins granted or removed. It lets each member see their own money trail without staff having to look anything up.

WHERE IT APPEARS (important correction): the history panel shows on the member's INVENTORY PAGE — specifically the page that contains the Currency System's inventory block. It does NOT appear on a member's profile or on any "Trade tab"; the plugin's older on-screen help that mentions "profile" or a "Trade tab" is out of date. Look for it on the inventory page.

This feature is OFF by default.

How to turn it on and shape it

  1. Open the Settings tab.
  2. Set "Show Profile History Panel" to Yes to reveal the panel (default is No).
  3. Optionally set "History Panel" — the title shown at the top of the panel. Blank = no title.
  4. Optionally set "Profile History Entry Count" — how many recent entries to display. Default 10.
  5. Optionally set "History Scroll Height (px)" — the maximum height of the list before it becomes a scroll box. Blank or 0 = default (240).
  6. Save.

Worked example: set "Show Profile History Panel" to Yes, "History Panel" to "My Wallet History", "Profile History Entry Count" to 15, and "History Scroll Height (px)" to 300. Each member now sees a titled box on their inventory page listing their 15 most recent transactions, scrolling past 300px.

Choosing what members see: MEMBER LOG TYPES

Under the MEMBER LOG TYPES heading is a list of Yes/No toggles, one per kind of action. Each controls whether that action type appears in a member's OWN history panel. Setting one to No hides it from members while STILL logging it for the admin log. The toggles:

  • "Member Log: Earned" — default No.
  • "Member Log: Bought" — default No.
  • "Member Log: Sold" — default No.
  • "Member Log: Deposited" — default No.
  • "Member Log: Withdrew" — default No.
  • "Member Log: Admin Granted Currency" — default Yes.
  • "Member Log: Admin Removed Currency" — default Yes.
  • "Member Log: Admin Granted Item" — default Yes.
  • "Member Log: Admin Removed Item" — default Yes.

Notice the pattern: everyday self-actions (earned, bought, sold, deposited, withdrew) default OFF, while admin actions (granted/removed currency or items) default ON. The idea is that members most need to see what staff did to their balance, and their own routine activity is optional.

TWO IMPORTANT CONDITIONS:

  • These toggles only matter if "Show Profile History Panel" is Yes.
  • An action can only be shown to a member if the Currency System actually RECORDED it in the first place. In the Currency System there is a "Record These Actions" setting; if an action type is not being recorded there, turning its member toggle to Yes here shows nothing, because there is no data. In other words: the Currency System must record it, THEN this toggle decides whether the member sees it.

ADMIN TRANSACTION-LOG VIEWER (STAFF ONLY)

TAB: Settings (control: "Log Viewer Header").

What it is: a STAFF-ONLY viewer that lists recorded transactions across ALL members. It appears automatically on your Currency System ADMIN page (the page that holds the Currency System's admin block). Ordinary members never see it. Unlike the member history panel, the log viewer works regardless of the "Show Profile History Panel" setting — it is always available to staff on the admin page.

Setting its heading, and how to use it

  1. Open the Settings tab.
  2. Optionally set "Log Viewer Header" — the title shown above the viewer. Blank = "Transaction Log".
  3. Save, then go to your Currency System admin page to use it.

On the admin page the viewer lets staff FILTER the log:

  • By username or member ID — type one or more; leave blank to show ALL members.
  • By action type — narrow to just the kinds of transactions you care about.

It displays these COLUMNS: Date · User · Action · Item · Qty · Amount · By. ("By" is who performed the action — useful for seeing which staff member made a grant.)

Worked example: to audit one member, type their username into the filter and pick the "Admin Granted Currency" action type; the table narrows to just the times staff added currency to that account, with dates and which admin did it.

Two things to know

  • The log viewer is themed as a PANEL. To change how it looks, use the Panels tab (it has no tab of its own) — it inherits the General Theme like any other panel.
  • Near the viewer on the admin page you may see an "unstuck member" tool. That tool is provided by the base CURRENCY SYSTEM plugin, not by CS Extras — CS Extras just sits nearby. If it is missing, that is a Currency System matter, not an Extras one.

CUSTOM CSS (ADVANCED)

TAB: Settings (control: "Custom CSS").

What it is: a text box where an advanced user can paste raw CSS to override ANY plugin styling. Whatever you put here wins over the presets, the General Theme, and every per-surface tab — it is the very top layer.

How to use it: open the Settings tab, scroll to "Custom CSS", paste your CSS rules into the box, and save. Blank = none (nothing added), which is the default.

Who should use it: only people comfortable writing CSS. For everything this manual describes, the tabbed color controls are the intended tools and you do not need this box. Reach for Custom CSS only for tweaks the tabs cannot express. If you paste something and a screen looks broken, clear the box to remove it — like everything else in this key-free plugin, it stores nothing permanent and is fully reversible.

QUICK TROUBLESHOOTING RECAP

  • Nothing looks different after install: expected. The default preset is CS Theme, which matches the base plugin's frosted look, so defaults change nothing. Start changing things on the General Theme tab.
  • A tool, the history panel, or the log viewer is missing: the Currency System is not installed, or it loads BELOW CS Extras. Put Currency System ABOVE Extras on the Plugins page.
  • A color I set has no effect: check the layer above did not disable it (e.g. "Show Borders = Hide" cancels any Border Color; "Show HUD Backdrop = Hidden" cancels the HUD Backdrop color), and confirm you are editing the right layer — a per-surface tab overrides the General Theme only for that one surface.
  • Rarity borders will not show: they must be enabled with tier colors in the Currency System (Styling + CSS and Shops tabs) first; the Item Cards toggles only display them. The Reward Popup's "Rarity Glow" is the one exception (drawn by the Minigame Suite).
  • The history panel is not on the profile: correct — it lives on the member's INVENTORY page, not the profile.
  • A member cannot see an action in their history: the Currency System must be recording that action ("Record These Actions"), AND its MEMBER LOG TYPES toggle must be Yes.
  • Remember the Golden Rule: leave a box BLANK to inherit; fill it only to override. To undo anything, blank it out again.
